# CynCo designs parts for the Bambu Lab P2S

Date: 2026-11-27. Status: built (one slice: design, check, picture, 3D view, slice). Proved end to end with the real programs on this PC by `bun engine/print3d/check.ts`; a live chat turn is the owner's check after the merge and the engine restart.

## What was asked

The owner bought a Bambu Lab P2S Combo and asked: "i want to make it so that cynco can be used to create and edit models of things i want to print with it", pointing at two projects to start from: MoraesGil/bambu-studio-mcp and heyixuan2/bambu-studio-ai. Asked which options fit the human-zoo-robots project, the owner chose, on the recommendation: OpenSCAD as the design language (approving its download), pictures from four sides plus an interactive 3D viewer in the dashboard, and a print-ready file the owner starts from Bambu Studio (CynCo never starts a print).

## What the owner can do afterwards

In any project chat, on the desk or the phone: describe a part ("a clip for the robot's 10 × 12 mm motor"), answer CynCo's questions about the dimensions that matter, and get the part as a picture from four sides and a 3D view to turn with a finger, with its size, whether it is closed and in one piece, its overhangs and plate contact, and whether it fits the P2S. Say what to change and get the next version; every version of the design is in the project's history. Ask for it sliced in a material and get the print time and grams for the P2S, and a `.3mf` to save from the chat (or open from the project folder) into Bambu Studio, where the owner presses Print.

How it is seen to work: the tests below, `check.ts` with the real OpenSCAD and Bambu Studio (a 20 mm cube: 1.3 s, 22 min, 3.8 g of PLA; the human zoo's motor-clip fit test, five slots at +0.0 to +0.4 mm: 3.2 s, 18 min, 4.5 g), the 3D viewer drawn and turned in a browser on this PC, and, after the merge, one live chat turn that builds a part and shows it.

## The two examples, and what was taken

- **heyixuan2/bambu-studio-ai** (MIT, 288 stars, maintained): an agent skill of Python scripts: parametric CAD (manifold3d), mesh analysis and repair (trimesh), previews, model-site search, paid cloud text/image-to-3D, headless slicing with Bambu Studio's command line, read-only printer status over MQTT. Its ground rule "the user starts the print" is kept. Taken, rewritten in TypeScript: how to drive Bambu Studio's command line (flags, a scratch folder, `result.json`) and how to flatten its presets (parent, then included templates, then the preset's own keys; identity never inherited), credited in `CREDITS.md`. Not taken: the Python runtime and its packages (the engine is Bun), the cloud generation (paid, not local), model-site search (later, if wanted), printer status (deferred).
- **MoraesGil/bambu-studio-mcp** (AGPL-3.0, new, experimental, macOS-validated): an MCP server that creates and edits Bambu 3MF projects and slices them with the installed Bambu Studio. Its 3MF revision editing is more than this slice needs; nothing was taken from it.

## The mechanism

One tool, `MakeModel`, in every project chat (`engine/print3d/CLAUDE.md` owns the detail):

1. The model writes `models/<name>.scad` with the ordinary file tools (the project chat's grader fences them to the project).
2. `MakeModel { file, slice?, material?, quality?, supports?, brim?, walls?, infill? }` builds it with the OpenSCAD on this PC into a work folder, after checking that the design reads only files of its project (`referenceFault`).
3. The engine reads the STL, measures it (size against the P2S's 256 × 256 × 256 mm, closed, pieces, inward faces, overhangs past 45°, plate contact), and draws four views into a PNG in software.
4. With `slice`, it flattens Bambu Studio's own P2S presets (0.4 mm nozzle; 0.24/0.20/0.16 mm Standard; the Generic filament preset of the material, because the owner's spools are third-party; the Textured PEI plate) and slices with Bambu Studio's command line into a print-ready `.3mf`, reading the time and grams back.
5. Outputs go to `models/<name>/`; the design and `report.json` are committed, the built files git-ignored.
6. The chat shows the picture (a file Image) and the model (a new RenderUI component, `Model3D`, drawn by the dashboard's own WebGL viewer, with Save buttons for the `.3mf` and `.stl`); the file route serves `.stl` and `.3mf` as downloads behind the same token and checks.

### The six questions

1. **What problem:** CynCo could not make or change a printable part, nor tell whether one would print on the owner's printer.
2. **Why the existing thing is insufficient:** a project chat can write files and run Bash, but a model driving OpenSCAD and Bambu Studio's command line by hand is the F176 shape (the image box's lesson: put the pipeline in the engine and have the model ask for what it wants), and nothing in the engine reads a mesh, draws one or shows one in 3D.
3. **What it adds:** a package (`engine/print3d`), a tool, a RenderUI component and its page viewer, two file types on the existing file route, a journal event, and two external programs it calls when present (OpenSCAD, Bambu Studio). No process that stays running, no new persistent store beyond the files in the project, no environment variable, no new dependency (pngjs and fflate were already dependencies). Failure modes: a program missing (a named refusal with the install command), a design that does not build (OpenSCAD's own lines back to the model), a design that reads outside the project (refused), a slice that fails (built and reported, "NOT SLICED" with Bambu Studio's reason), a planted link where outputs go (refused), Stop and the caps (the process tree ended).
4. **How it is verified:** 57 new tests (`engine/__tests__/print3d/`, the Model3D blocks of `dashboard/genui.test.ts`), the suite and guards, `check.ts` with the real programs, the viewer in a browser.
5. **How it is disabled, recovered or removed:** take `MakeModel` out of `PROJECT_TOOL_NAMES` (one line) and the chat no longer has it; uninstalling OpenSCAD or Bambu Studio turns the build or the slice into a named refusal; a project's `models/` folder is plain files and can be deleted; removing the package means removing the tool from the registry, the `Model3D` entry from the catalog and the viewer from the page.
6. **Who maintains it:** this repository; Bambu Studio's preset names for the P2S are read from its install at run time, so a Bambu Studio update that renames one is a named refusal, not a wrong slice.

### Review triggers this change meets

- **The project chat's prompt grows** (static, so the prefix cache is rebuilt once after the restart): a `PROJECT_WORK` line for 3D prints, the MakeModel tool definition, and the Model3D signature in the RenderUI section, whose project bound in `engine/__tests__/genui/prompt.test.ts` went from 13,000 to 13,300 characters (it stood at 12,996). A coding session's RenderUI section does not list Model3D and is unchanged in size.

- **A separately running process:** OpenSCAD and Bambu Studio, each started for one call through the containment layer's spawn (`runProgram`), its tree owned and ended on its cap and on Stop; nothing stays running.
- **A protocol change:** an engine-only `model` field on a RenderUI element (`UiModelState`), set by the engine like `image`, dropped when the model writes it.
- **Widening what the file route serves:** `.stl` and `.3mf` files of a project, by the same path rule, the same token, the same no-link and one-name checks, a format check of their own, a 64 MB cap, as attachments. A paired phone could already read every file of a project through the chat; this serves the model's own outputs.
- **Autonomous authority to run programs:** the tool runs OpenSCAD on a design the model wrote. OpenSCAD's language cannot run a program or write a file; it can read, which `referenceFault` fences to the project. It runs without asking, as `RenderUI`'s pictures do; the chat's Bash would ask for running a program in the project, and the owner's ask was for the chat to make models.

## Measured on this PC (2026-11-27)

- Bambu Studio 02.09.02.62 was already installed, with P2S machine, process and filament presets; OpenSCAD 2026.11.27 Nightly installed by winget (hash verified) on the owner's yes.
- The headless slice works: a 20 mm cube in about a second of slicing. Flattening without the `include`d templates sliced it with a generic parent's start G-code (9 min); with them, the P2S's own (22 min: heating and levelling included). The sliced project names the P2S, its process, the filament and the Textured PEI plate, and carries the P2S's layer-change G-code.
- Bun 1.3.13 does not start OpenSCAD's `openscad.com` named by a path with backslashes (ENOENT, "not found in $PATH"); `openscad.exe -o` gives the same lines on stderr and the same exit codes. The first live check failed on it; the unit tests had passed under vitest's Node.
- The four-view picture of a 2,692-triangle part renders in about 100 ms; the 3D viewer draws and turns it in the browser pane.

## What it does not do

- Start, pause or watch a print, or read the printer's state: deferred by the owner on 2026-11-27 (LAN mode, an access code and a yes per print would be needed to start one).
- Make organic shapes (the human zoo's specimen figures): OpenSCAD is for parts with dimensions. The route proposed is image → 3D on the image box (imagegen already leaves room for it), then OpenSCAD to fit the mesh to the chassis; not built.
- Multi-colour or AMS assignment; a 3MF or OBJ as a direct input (OpenSCAD can `import()` both inside a design); thin-wall detection; mesh repair.
- Take a model file uploaded from the phone (the upload route accepts documents and pictures, not meshes).
- Know the owner's actual filament: time and grams are Bambu Studio's prediction for the Generic preset of the material.
