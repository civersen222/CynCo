# engine/genui

## Purpose
Generative UI for the 9161 dashboard: the model draws tables, plans, charts, key facts, forms and buttons in the chat pane through one tool call, `RenderUI`, and the page's clicks come back to it as its next user turn. This package owns the component vocabulary (`catalog.ts`), the validator that turns whatever the model wrote into something the page can draw (`spec.ts`), the prompt section that teaches the tool (`prompt.ts`), the progressive parse of a half-streamed call (`partial.ts`), the click → user-turn formatter (`actions.ts`), the tool itself (`renderUiTool.ts`) and the classifier that decides when a project chat must answer with a surface (`intent.ts`). The conversation loop (`engine/bridge/conversationLoop.ts`) emits the `ui.render` frames and accepts the `ui.action` command; the page (`engine/dashboard/index.html`) renders with vanilla DOM. It must never throw on model input, never present a cut-off spec as final, never leave a partially drawn surface without a terminal frame, and never let a model-authored string reach the page unescaped. The format, vocabulary and prompt rules were adopted from OpenUI, json-render and A2UI (see `CREDITS.md`); none of their renderers could be used (React/Lit, no no-build bundle), which is why the page's renderer is hand-written.

## Key files
| File | Role |
|---|---|
| `catalog.ts` | `GENUI_CATALOG`: 42 components in seven groups with typed props, children policy, description and example — the single source the validator, the prompt and the dashboard tests read. An `Image` takes a `prompt` the engine paints (`engine/imagegen`, F174) — with an optional whole-number `seed` (type `int`: a safe non-negative integer, coerced from `"1001"`, anything else dropped with a note that shows at most 60 characters of it), another take of the same prompt (F176) — a real URL in `src`, or in `src` the project-relative path of an image file the model wrote (shown through the file route); 3D is left for imagegen's later image → 3D step. |
| `spec.ts` | `validateSpec`: name resolution, field relocation, shape coercion, limits, reachability, Button/Form and Tabs rules; lenient `partial` mode for streaming frames. `projectImagePath`: the one rule for an Image `src` that names a file in the project, which the page (`GENUI_IMAGE_PATH_RE`) and the file route (`servedProjectFile`) check again. |
| `prompt.ts` | `genuiPromptSection`: the static `<RENDER_UI>` section (when the surface IS the answer, shapes, arguments, eleven rules, an options example and a plan example, grouped signatures), built once from the catalog. |
| `partial.ts` | `parsePartialSpec`: jsonrepair + partial validation over the streaming tool-call buffer; `PARTIAL_FRAME_INTERVAL_MS`. |
| `actions.ts` | `formatUiAction` / `uiActionEcho`: the user turn a click becomes, bounded per section. |
| `renderUiTool.ts` | `renderUiTool` (`RenderUI`): the envelope `inputSchema` the server turns into a grammar, and the result text whose notes (already shown to the user) say what was dropped or changed. |
| `intent.ts` | `uiRequestReason`: does a user message ask to SEE options, designs, pictures, a comparison or a table? A project chat then forces its calls with `tool_choice: 'required'` until a surface draws (F171). |

## Important types & functions
- **`GENUI_CATALOG`** (`catalog.ts:64`) — the component table; `GENUI_COMPONENT_NAMES` (`catalog.ts:394`) and `GENUI_GROUPS` (`catalog.ts:397`) derive from it; `resolveComponentName` (`catalog.ts:404`) resolves a model's spelling case-insensitively.
- **`validateSpec`** (`spec.ts:481`) — `(raw, { partial? }) → { spec | null, errors, count }`; never throws. Strict mode reports every lossy decision for the model; partial mode skips silently (design A3).
- **`LIMITS`** (`spec.ts:19`) — 300 elements, 500 array items, 8k chars per string, depth 24, id pattern; `isSurfaceId` (`spec.ts:46`) is the surface-name check the loop and the page share.
- **`genuiPromptSection`** (`prompt.ts:184`) — `(mode: 'project' | 'session')`, one byte-stable section per mode: a project chat makes the surface THE answer for options, designs and choices; a coding session (possibly the TUI, which draws no surface) keeps its answer in prose with the surface alongside, and is told to leave prompted pictures and file Images out, since both are shown in project chats only. Past the opening the two differ only in the picture wording (`PICTURES`): the project chat's Shapes line gives each design a prompted Image framed for a later 3D model, says a prompt may be as long as the design needs (whole paragraphs), that several takes of one design are several Images with one prompt and different `seed`s, and that the engine paints — "never call an image server, write a ComfyUI workflow, or save renders yourself" (the one static mention of ComfyUI in the prompt; the live run of 2026-10-12 drove the server through Bash, F176); rule 5 names the whole-number `seed` of a take among the ideas the model authors (its "never invent" numbers would otherwise forbid one) and says to describe a picture in `prompt`, rule 11 says pictures fill in by themselves and its options example carries prompted Images; the session's section asks for no picture anywhere — the pre-F174 Shapes line and rule 5, and the same example without its Images — so its opening is never contradicted (F174). `genuiExampleCall` (`prompt.ts:194`) is the plan example the tests and the page demo reuse, `genuiOptionsExampleCall` (`prompt.ts:189`) the project chat's options example (a Grid of Cards, each with a prompted Image and a Button).
- **`parsePartialSpec`** (`partial.ts:34`) — null until a root exists; carries `surface` only once it is complete and valid. `trimOpenScalar` (`partial.ts:25`) drops a bare number or literal the buffer ends inside, so `"max": 1` (on its way to 10) never reaches a frame.
- **`formatUiAction`** (`actions.ts:48`) / **`uiActionEcho`** (`actions.ts:40`) — the structured body and the echo line; `UI_ACTION_SECTION_CAP` (`actions.ts:14`). **`isFollowUp`** (`actions.ts:28`) — a FollowUps chip (`action: 'followup'`, `UI_FOLLOWUP_ACTION` at `actions.ts:25`) whose text becomes the user turn verbatim.
- **`actionFromLabel`** (`spec.ts:669`) — the socket-safe action id a Button gets from its label when it has no action (OpenUI semantics), and the normaliser for any action name the socket would refuse.
- **`renderUiTool`** (`renderUiTool.ts:59`) — `core: false` (loadable in a coding session), always in `PROJECT_TOOL_NAMES` (`engine/projects/profile.ts:18`); `RENDER_UI_INPUT_SCHEMA` (`renderUiTool.ts:20`) declares `surface` before `spec` so partial frames can carry it.
- **`ConversationLoop.handleUiAction`** (`engine/bridge/conversationLoop.ts:947`) — idle: the click is the next user turn; busy: queued in `pendingUiActions` and drained at the turn's natural end (`engine/bridge/conversationLoop.ts:4146`) or re-dispatched from `runTurn`'s finally (`engine/bridge/conversationLoop.ts:1468`).
- **`ConversationLoop.emitFinalUiRender`** (`engine/bridge/conversationLoop.ts:1048`) — the one final frame per call, before `tool.complete`; `closePendingUiSurfaces` (`engine/bridge/conversationLoop.ts:1002`) owes every partial surface a terminal frame carrying the reason, and logs each as `[genui] surface <toolId> withdrawn (<path>): <reason>`; `dropToolBatch` (`engine/bridge/conversationLoop.ts:1022`) answers every call of a batch the loop skips (the context-critical stop) with a tool result under its own id, so a surface that drew is withdrawn with that reason and the model is told.
- **`uiRequestReason`** (`intent.ts:136`) — the matched words when a message asks to see something drawn, else null; never for a click's user turn (its `[UI action]` line) and blind to quoted, fenced, `>`-quoted and pasted-for-editing text. `UI_FORCE_MAX_CALLS` (`intent.ts:22`) bounds the forced calls per message.
- **`drawsContent`** (`spec.ts:690`) — whether a validated spec draws anything besides spacing, unknown-component notes and untitled containers; only such a surface releases forcing.
- **`projectImagePath`** (`spec.ts:427`) — `(src) → path | null`: the project-relative path of an image file the model wrote — '/'-separated ASCII segments of letters, digits, `_ - . ( )` and single inner spaces, none starting with a dot (so never `.`, `..`, `.git` or `.cynco`), ending in png, jpg, jpeg, gif, webp or svg, no scheme, no leading `/` or drive letter, no backslash, no `..`, at most `PROJECT_IMAGE_PATH_MAX` (`spec.ts:436`) = 200 characters — trimmed, with a leading `./` removed. `PROJECT_IMAGE_PATH_RE` (`spec.ts:435`) is the pattern the page copies verbatim (pinned by `engine/__tests__/dashboard/genui.test.ts`).
- **`ConversationLoop.uiForce`** (`engine/bridge/conversationLoop.ts:624`) — set for each new user turn by `setUiForce` (`engine/bridge/conversationLoop.ts:985`): a typed message (`engine/bridge/conversationLoop.ts:2044`) or a click delivered at a turn's end, in a project chat whose RenderUI survives the profile's scoping (`renderUiScoped`, `engine/bridge/conversationLoop.ts:975`); while set, `forceUi` (`engine/bridge/conversationLoop.ts:3483`) puts toolChoice 'required' on the call and an AskUser call is answered "draw it with RenderUI" instead of asked (`engine/bridge/conversationLoop.ts:4988`).
- **`isTruncatedJson`** (`engine/engine/toolCallRepair.ts:54`) — the cut-off signal: an object, array or string still open at the end of the arguments. `callModel` puts it on the `repaired` transport event as `truncated`.

## Data flow
1. A turn that offers `RenderUI` (every project chat; a coding session after `load_tools`) gets the `<RENDER_UI>` section appended to its prompt (`engine/bridge/conversationLoop.ts:2038`). In a project chat, a message that asks to see options, designs, pictures, a comparison or a table (`uiRequestReason`) sets `uiForce`: its model calls go out with `tool_choice: 'required'` until a RenderUI surface draws, at most `UI_FORCE_MAX_CALLS` of them.
2. The model calls `RenderUI({ surface, spec })`. While the arguments stream, the loop feeds the `input_json_delta` chunks to `parsePartialSpec` at most every `PARTIAL_FRAME_INTERVAL_MS` and emits `ui.render { partial: true, surfaceId: toolId }` frames.
3. `executeOneTool` runs the tool (validate, answer with count + notes). Before `tool.complete`, `emitFinalUiRender` validates once more, appends ` (surface: <id>)` to the result, hands the spec to the image annotator when the engine wired one (`engine/imagegen`, F174: each prompted `Image` gets its picture state on the frame and the result its `Pictures:` line) and emits `ui.render { partial: false }` under the surface the model named (or the toolId); the picture jobs start only after that frame. A refused, malformed or errored call gets `spec: null` with the reason; a spec whose arguments were cut off mid-stream (`isTruncatedJson`) is drawn but reported as cut off.
4. The page renders the surface; a Button, an actionable List item or a FollowUps chip sends `ui.action` (bounded at the socket by `commandSchema.ts`), which `main.ts` routes to `handleUiAction` → `formatUiAction` (a chip: its text verbatim) → a user turn; the model answers and may re-render the same surface id.

## Gotchas
- Partial frames ALWAYS use `surfaceId === toolId`; only the final frame carries the model's surface id. The page keys on `data-tool-id` first and re-labels on the final frame, else every named surface would render twice (design A1; pinned by `engine/__tests__/bridge/uiRenderWiring.test.ts`).
- Partial emission is gated on `offeredToolNames.has('RenderUI')`: a model that remembers the tool from history without it being offered is refused before the executor, and a partial surface for a refused call would have no final frame. Every path that opens a surface closes it — the batch loop after `executeOneTool` and `runTurn`'s finally — so an abort, halt or refusal still sends `spec: null` (design A2). A withdrawal always carries the real reason: an exit that skips a batch with calls still in it answers each call (`dropToolBatch`: the context-critical stop, and a stream cut by a transport error mid-turn — callModel swallows a retryable one into an `api_retry` notice and returns without `message_stop`, so the loop tracks `message_stop` itself and ends such a turn through the error path with the cut as the reason, instead of taking the half-turn for `end_turn`), and the contract's read-loop evasion probe runs its iteration's calls and nudges after them. All three used to drop the calls unexecuted, so the next batch end found no tool result under the streamed id and withdrew a surface the page had already drawn as "the call did not run", with the model never told (F175, dashboard transcript 2026-10-11, the "Tower design brief" form and the tower Cards; the cut stream was found in review). That fallback text now means an unknown path and is logged as such; pinned by `engine/__tests__/bridge/uiRenderWiring.test.ts`.
- `validateSpec` is lenient on purpose: it coerces `"2"` → 2, string option lists, `data: [{label,value}]` charts, row objects, nested trees and A2UI/OpenUI action objects, and reports only what it dropped. An unknown component becomes a visible error `Callout` AND an issue line — a silent drop is the OpenUI failure mode the design rejected.
- The tool returns `isError` only when nothing is drawable; a cosmetic issue must not trip the per-tool circuit breaker on the one tool whose output the user is looking at.
- The result's notes header and prompt rule 11 send the model back only for "an element that was dropped" or a cut-off spec, so every note for something not drawn — a bad id, a non-object, an unknown component, a child naming no element, a missing required prop — says "the element was dropped" in those words; a note for something changed but drawn does not.
- The prompt section is static text and is pushed only when the tool is offered — the same condition that already rewrites the tool list, so the prefix-cache rule (`engine/engine/CLAUDE.md`) holds.
- `ui.action` is bounded twice: the socket refuses ids over 128 chars, text over 2k and objects over 8 KB (`commandSchema.ts`), and `formatUiAction` truncates each section at 4 KB — a read-scoped page must not be able to push a multi-megabyte user turn into the model.
- A click that lands while a turn runs is never handed to the busy guard (which drops interactive messages): it waits in `pendingUiActions` and is delivered at the natural end or re-dispatched after any other exit. In a coding session it skips DoD contract auto-create (`TaskOpts.uiAction`) — a form submit is not a task.
- A turn whose only tool was `RenderUI` gets no "summarize what you did" follow-up: narrating a card under the card is noise.
- "Cut off" is measured on the raw arguments (`isTruncatedJson`), never inferred from `stop_reason` or from jsonrepair having run. On the native streaming path `stop_reason` reads `tool_use` for any call with a tool block (`streamTranslator` synthesizes it), and jsonrepair also fixes trailing commas and quotes; reporting those as "cut off by the output limit" told a model to shrink a complete spec.
- Best-of-N candidates run on the same loop with `ui.render` muted; their pending surfaces are cleared when the real `emit` is restored, or a terminal frame under the real emit would draw a withdrawn box the page never saw.
- Action names are normalised to the socket's id rule (`/^[A-Za-z0-9_-]{1,128}$/`) in the validator and again on the page: a Button with action `"Plan trip"` would otherwise be refused at the click.
- An `Image` takes `prompt` (a description the engine paints on the operator's ComfyUI, `engine/imagegen/CLAUDE.md`; whitespace-normalised, at least 3 characters, bounded only by `LIMITS.stringChars` — a 1,000-character cut sent the model to paint by hand, F176, live run 2026-10-12) or `src` (a real http(s)/`data:image` URL, or the project-relative path of a png/jpg/gif/webp/svg file the model wrote — `projectImagePath`), exactly one (F174), and with a prompt an optional `seed` (another take: `"1001"` → 1001, 0 … 2^53−1 kept, a fraction, a negative, a bigger number, a boolean or a word dropped with a note showing at most 60 characters of the value — a prompt in the wrong slot is kilobytes, and the note rides the tool result and the final frame; a seed beside a `src` is dropped as meaning nothing). `validateSpec` folds `Src`/`Prompt`/`Seed` in any letter case onto those names first (`coerceProps` takes any case, so the checks must too), keeps a `src` that is such a path as written (trimmed, `./` removed; whether the file exists is not the validator's call), drops any other `src` with a hint — the path rule for a src with no scheme (so a file named with a backslash, a non-ASCII letter or a `?v=2` can be renamed), the URL forms for one with a scheme, both saying to describe the picture instead — a made-up name is never turned into a prompt — keeps the prompt when both are given, and drops an Image with neither; an element-level `image` the model writes is dropped, so only the engine sets a picture's state. Pictures are generated only from the one final frame, never from a partial frame, never in a best-of-N candidate (`inBestOfN` on the loop) and never for a cut-off spec (the annotator turns those off with the reason); the jobs run beside the turn, and `ui.image` is keyed on the image key, never on a surface. A path `src` is annotated by the same hook as prompted pictures (`ImageService.annotate`, `engine/imagegen/CLAUDE.md`; `withValidatedSurfaces` on reload): in a project chat the element gets the engine-only `image: { status: 'file', slug, path }` and the src leaves its props, so the page reads the path from the annotation alone; in a coding session it gets `off: files are shown in project chats only`; a file that is not a regular file inside the project is named in the result's `Files:` line (the page shows the route's answer). A loop without an annotator leaves the path in props and the page draws the alt placeholder. Before this, the model that wrote 1:1 printable SVG templates into a project and showed them as Images saw every one dropped as "not an http(s) image URL" (F175, dashboard transcript 2026-10-11).
- The page (`engine/dashboard/index.html`, section "Generative UI") never fetches a remote `Image` unasked: the model chose the URL and a URL can carry anything it read, so a placeholder with "Load image from <host>" stands in until the user clicks (no referrer); while the call streams, a URL Image is a neutral placeholder with no button (the URL may be half a host). A generated `Image` (a `prompt`) needs no click: the engine chose and made it, so the page builds the same-origin URL from the annotation's key and slug (both pattern-checked, never read from the spec), fetches it with the token through the injected fetch wrapper and shows a blob URL (a file that is an SVG: a `data:` URL, never a blob — a blob: URL has the dashboard's origin, and "Open image in new tab" on a model-written SVG would run its `<script>` there, where it can fetch the served page and read the token embedded in it; a `data:` document has an opaque origin; F175 review) — a bare `<img src="/api/…">` carries no token and is refused. Its box takes the picture's shape from the first frame (`aspect-ratio`), so filling in never moves the card; it shows "Picture comes when the card is finished" on a partial frame (and "picture not generated (the card was not finished)" once that surface is withdrawn, since no final frame follows), the alt and the reason when off, a pulse while queued or running (none under reduced motion), the reason when failed, and the picture when done, which a click enlarges with a Download link. A file Image (`status: 'file'`) is drawn by the same code as a done picture under the map key `file:<path>`: the path is checked against the page's copy of the validator's rule (`GENUI_IMAGE_PATH_RE`, with the 200-character and `..` checks) and a bad one draws "bad file reference"; the URL is `/api/projects/<slug>/files/<path>` with each segment `encodeURIComponent`-ed (`genuiFileUrl`); any `image/*` type is accepted; the box has no fixed shape; a failed load says "<path> could not be loaded (HTTP n)"; the lightbox shows the path where a prompt would go and its Download is named after the file; and because the file can change, every new final frame that shows it marks the entry stale (`genuiMergeFile`) and fetches it again while the old picture stays up until the new blob is in (the old URL is then revoked); one read runs at a time, and a frame that lands while one is in flight gets its own read once that one answers, whatever the answer, so the last frame's read is always the last one made. It is only ever put in an `<img>` (an SVG there runs no script and loads nothing), never inline, never through innerHTML; the recheck after a reconnect skips files. `genuiImages` (`<slug>/<key>` → status and blob URL) outlives every re-render; it is keyed on the project as well as the key, because the key hashes how a picture is made, not where, so two projects asking for one prompt run two jobs under one key and one project's event must never fill or fail the other's card. Merging: done never goes back (except that the page's own failed load marks it failed), a fresh queued/running replaces a failure, otherwise the more advanced status wins with done above failed — so a `done` after a failed load (an event, a recheck, a re-render that finds the picture made) fetches it again; `ui.image` refills every figure with that key in that project, `ws.onopen` re-asks the record of each picture still in flight (`genuiRecheckImages`, a `done` sent while the socket was down is otherwise lost) and the blob URLs are freed whenever a conversation leaves the pane: `clearChatPane` (also the new-chat path of `onProjectOpened`) forgets the whole map, while a redraw — `openProjectChat` after its transcript, `onProjectOpened`'s reconnect into another chat — keeps it and then frees only the keys no figure shows (`genuiPruneImages`), because a `ui.image` that landed while the transcript loaded is newer than the record the server read. A long reason scrolls inside the fixed box. A partial frame draws input values but never seeds the surface state (`genuiInit`), so a half-written value cannot beat the final frame's. A replayed transcript spec is unvalidated, so the page keeps its own bounds: no revisits, depth 32, 400 elements, each component drawn in its own try/catch.
- Element ids, child ids and input names are model-chosen keys, so `validateSpec` keeps them in `Object.create(null)` maps read through `Object.hasOwn`, refuses `__proto__`/`constructor`/`prototype` as ids (`RESERVED_KEYS`, `spec.ts:51`) and renames such an input to `field-<name>` (`__proto__` → `field-proto`): a Tabs child id of `__proto__` resolved to `Object.prototype`, and the Tabs rule then wrote `tab` onto every object in the engine.
- An element is placed at most once. A child that is already placed — the root, an ancestor, or a second parent's child — is skipped with "is already placed (a cycle or a second parent)", and the ancestor walk is bounded by `LIMITS.depth`. Before this, a child pointing back at the root, with an action-less Button in the tree, hung the validator, and with it the engine, inside `executeOneTool` (final review).
- A failed or refused call withdraws only its own box: its terminal frame is keyed on its `toolId`, never on the surface id it named, so a bad re-render of `plan` cannot erase the `plan` the user is looking at. The page withdraws a replayed failed call the same way.
- A click is drained at the natural end only on the real loop (`loopOpts?.candidate ? undefined : …`); a best-of-N candidate that drained it would answer it into a discarded transcript. A queued click whose re-dispatch finds the loop busy again goes back on the queue rather than to the busy guard.
- A reloaded project chat replays the transcript through `withValidatedSurfaces` (`engine/projects/api.ts:174`): the page receives what `validateSpec` made of each stored RenderUI input — the same thing it drew live — with each generated `Image`'s current picture state found through `images/index.json` (F174) and each file Image annotated afresh (`annotateFileImages`), and the stored history is left as written.
- The page's markdown autolinker stashes every anchor it generates behind a placeholder before emphasis and URL passes run, so a URL is never linked a second time inside an `href` (that nesting let `"` break out of the attribute).
- Forcing (F171) exists because wording alone failed live: asked "show me a few different designs", Qwen3.8-27B weighed RenderUI and wrote four markdown sections. `tool_choice: 'required'` changes only llama-server's grammar — the template gets the same `tools` array, so the system prompt, tool list and cached prefix are identical to an `auto` call (pinned in `uiForceWiring.test.ts`). Text before the call is still allowed; what is gone is ending the turn without one. It is project-chat only (the TUI does not draw `ui.render`), never in a best-of-N candidate, only on a call that offers RenderUI AND whose RenderUI survives the profile's `config.tools` scoping (callModel filters after the loop — forcing a call without RenderUI would force some other tool), released by the first final frame that draws content (`drawsContent`: a Grid of "Unknown component" notes does not count), at the call after the `UI_FORCE_MAX_CALLS`-th forced one (so the last forced call's AskUser is still redirected), and at the end of the turn. A click delivered at a turn's end is a new user turn: `setUiForce` runs on its text, so a FollowUps chip asking for more designs is forced exactly as when sent idle, and a Button click clears forcing. A server that refuses `required` gets `auto` for the rest of the session (`engine/llama/CLAUDE.md`), and each such call logs `[llama-cpp] tool_choice=required NOT SENT`; simulated and no-tools modes cannot force and the `[callModel]` log line says `tool_choice=required NOT SENT`.
- While forcing, AskUser is the likely wrong pick (a choice → an ask card): it is answered with a non-error result telling the model to draw the options, and not counted against the tool's trust score.
- The dashboard's "Show as UI" link (under every project-chat reply, next to "Save as artifact") sends its text as a followup `ui.action` (surface `show-as-ui`), not a `user.message`: a click during a running turn is queued instead of being dropped by the busy guard. Its text ("Show your previous reply as UI with RenderUI …") is one `uiRequestReason` forces — the manual path for options the model offered unasked. Both links always name their reply by its opening words (`replyReference`; "the previous reply" alone is wrong after a surface-only turn), with the excerpt's quotes turned into apostrophes, and the classifier cuts the page's lead-in ("the reply to show is the one that begins:") off before matching, so the excerpt can neither trigger nor veto.
- The classifier leans precise (final review, an 80-message corpus): project chats are about builds, recipes and stories, so "on the table", "into the form", "build a dining table", "the plot of chapter two", "the two aliens compare their ships" and "3 vs 4 coats" must not force. Imperatives count only where they address the assistant (clause start, "can you", "and", "please"… or "show me"), weak nouns (looks, directions, ways, plans) only after a quantifier, picture nouns (pictures, images, illustrations) like designs since a project chat's Image paints its prompt (F174) but "renders" only after a quantifier or before "of" ("show me how the page renders" is the verb), "table"/"plot" only when what follows holds data, and "x vs y", "torn between" and "which … or" outside a "which is better/would you recommend" frame are left to the prompt.
- A surface carries the answer's details in a project chat, so the citation scan reads RenderUI inputs as well as prose; the page clears the previous Sources line when a turn is sent, since a surface-only turn opens no prose bubble to clear it.
- Whether llama-server streams tool arguments in many deltas is not measured in this repo (the stream probe checks only that the whole buffer parses); if it sends them in one or two chunks, partial frames simply never fire and the final path is unaffected.
