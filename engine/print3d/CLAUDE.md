# engine/print3d

## Purpose
3D printing from a project chat (owner's ask of 2026-11-27, a Bambu Lab P2S Combo; record `docs/decisions/2026-11-27-3d-printing.md`). The model writes a part as an OpenSCAD design under `models/` with the ordinary file tools and calls **MakeModel**: the engine renders it with the OpenSCAD on this PC, measures the mesh the way a slicer would care (size against the P2S's build volume, closed or not, pieces, faces pointing inward, overhangs past 45°, plate contact), draws it from four sides into a PNG in software, and, when asked, slices it with Bambu Studio's own command line and its P2S system presets into a print-ready `.3mf` with the print time and the grams. Editing a model is editing its design and building again; the design and a small `report.json` are committed to the project's history on every build, the built files are git-ignored. The chat shows the picture with a RenderUI `Image` and the model with a `Model3D` (the dashboard's own WebGL viewer, `engine/genui/CLAUDE.md`), whose Save buttons hand the `.3mf` or `.stl` to the browser. Nothing here talks to the printer: the owner opens the `.3mf` in Bambu Studio and presses Print. This package imports from `engine/projects/` (layout, history, the tool context), `engine/containment.ts` and `engine/processTree.ts`; nothing imports it but the tool registry (`engine/tools/registry.ts`). Status: wired, in every project chat (`PROJECT_TOOL_NAMES`, `engine/projects/profile.ts`); proved end to end with the real OpenSCAD 2026.11.27 and Bambu Studio 02.09.02.62 on this PC by `check.ts` (2026-11-27), not yet in a live chat turn.

## Important types & functions
- **`makeModelTool`** (`tool.ts:52`) — `{ file, slice?, material?, filament?, quality?, supports?, brim?, walls?, infill? }`; refuses by name outside a project chat (`getProjectToolContext`), answers `isError` when the build or an asked slice failed. `tier: 'auto'`, `core: false`. Its path row is `MakeModel: { fields: [{ key: 'file', op: 'read' }] }` in `TOOL_PATH_TABLE` (`engine/tools/toolPaths.ts`).
- **`parseAsk`** (`tool.ts:22`) — booleans also as `"true"`/`"false"`, numbers as text; walls 1–20, infill 0–100, quality draft|standard|fine; a slice setting without `slice: true` is refused with the names (the model asked for something it would not get).
- **`makeModel`** (`build.ts:123`) — `(dir, ask, deps, signal) → { ok, text, report? }`, never throws. A `.scad` (under 4 MiB) or an `.stl` (under `STL_MAX_BYTES`, `mesh.ts:47`), a regular file really inside the project with one name. Then: `referenceFault`, OpenSCAD into the work folder, `readStl`, `plateOf`, `analyzeMesh`, `renderSheet`, the outputs written, the slice when asked, a stale print-ready `.3mf` removed when not, `report.json`, the journal (`model.built`), the commit of the design, the report and the ignore file. The text tells the model the size, the checks, the warnings, the estimate, the files and how to show them, and that it never starts a print.
- **`outputFolder`** (`build.ts:73`) — `models/<path>.scad` → `models/<path>/`; a source anywhere else → `models/<its name>/`; every segment `slugify`d, so the files always pass the file route's path rule.
- **`referenceFault`** (`openscad.ts:114`) — reads the design and every project file it includes (depth 8, 64 files): an absolute path, a computed file name (`import(f)`), a path that lands outside the project (links followed, `realInside`) or a library name that climbs with `..` is refused with the file and line; a bare library name that is no project file is left to OpenSCAD's own library folders (OPENSCADPATH is not passed on, `buildStl`). `designReferences` (`openscad.ts:93`) finds them in `codeView` (`openscad.ts:63`): comments blanked, and string contents blanked for the search, so a word in a string or a comment is no reference.
- **`buildStl`** (`openscad.ts:189`) — `openscad.exe -o <work>/<name>.stl --export-format binstl <design>` in the design's folder under `OPENSCAD_CAP_MS` (`openscad.ts:24`, 180 s); errors, warnings and echoes back to the model (`parseMessages`, `openscad.ts:155`, 20 lines each), each failure named (did not run, stopped, timed out, exit code, no STL).
- **`analyzeMesh`** (`mesh.ts:106`) / **`meshWarnings`** (`mesh.ts:186`) — corners welded on their exact coordinates (OpenSCAD and slicers write them shared), edges counted (1 = open, >2 = non-manifold), shells by union-find, signed volume (negative = inward faces), overhang = downward faces steeper than 45° more than 0.25 mm above the lowest point, contact = flat downward faces at it; the warnings say what each means for the print, worst first.
- **`renderSheet`** (`render.ts:42`) — 2 × 2 tiles of `DEFAULT_TILE_PX` (`render.ts:35`, 480), each fitted to the part and a 10 mm grid on the plate under it; a face seen from behind is red; edges darkened from depth jumps; the size and the title written in a 5×7 font (upper-case ASCII; anything else skipped).
- **`flatten`** (`slicer.ts:129`) — a Bambu Studio preset in the order Bambu Studio loads it: the `inherits` chain, then the `include`d templates, then its own keys; `name`, `setting_id`, `instantiation`, `from`, `type` never inherited, `filament_id` never from a template; null on a missing link or a loop.
- **`choosePresets`** (`slicer.ts:168`) / **`processSettings`** (`slicer.ts:199`) — the P2S 0.4 machine, the process by quality (`0.24/0.20/0.16mm Standard @BBL P2S`), the filament by material (`MATERIALS`, `slicer.ts:46`: the Generic presets, because the owner's spools are third-party) or an exact preset name checked against `compatible_printers`; the plate from the machine model's `default_bed_type` (Textured PEI); supports `tree(auto)`, an 8 mm outer brim, wall loops and infill only when asked.
- **`slice`** (`slicer.ts:244`) — writes the three flattened presets into a fresh work folder, runs `bambu-studio.exe --load-settings machine;process --load-filaments filament --arrange 1 --orient 0 --slice 0 --outputdir <work> --export-3mf sliced.3mf <stl>` under `SLICE_CAP_MS` (`slicer.ts:59`, 300 s), reads `result.json` (`readEstimate`, `slicer.ts:211`: time and grams summed over the plates, a failure's `error_string`) and the version the project records (`slicerVersion`, `slicer.ts:273`).
- **`runProgram`** (`run.ts:28`) — `toolSpawnRefusal`, `containedCommand`, `ownedExec` with `ownProcessTree` and the turn's signal, the launcher's faults read with `launcherFaultOf`: the shape `engine/lsp/manager.ts` uses for a program and its arguments. An output past 16 MiB, a program that cannot start and a containment refusal are `refused` with the reason, never an exit code.

## Data flow
1. The model writes `models/<name>.scad` (Write/Edit, graded by `gradeProjectCall`) and calls `MakeModel { file }`.
2. `makeModelTool` → `parseAsk` → `makeModel(projectDir, ask, deps, signal)`.
3. `readSourceFile` (one name, really inside, capped) → `outputFolder` → `folderFault` on the output folder and `.cynco/tmp` → `mkdtemp` of a work folder under `.cynco/tmp`.
4. A design: `referenceFault` → `findOpenScad` → `openScadVersion` → `buildStl` into `<work>/<name>.stl`. A mesh: copied into the work folder.
5. `readStl` → `plateOf` (the machine preset's build volume, or `PRINTER.plate`) → `analyzeMesh` → `meshWarnings` → `renderSheet`.
6. `<name>.stl`, `<name>.png` and `.gitignore` written with `writeBytesAtomic` (`engine/projects/layout.ts`).
7. With `slice`: `choosePresets` → `slice` in `<work>/slice` → `sliced.3mf` renamed to `<name>.3mf`. Without: a `<name>.3mf` left from an earlier build is removed (it no longer matches the design).
8. `report.json` (`writeJsonAtomic`), `appendJournal(model.built)`, `ensureHistory` + `commitHistory([report.json, .gitignore, journal.md, the design])`; the work folder is removed.
9. The model shows the result with RenderUI: an `Image` with `src` the PNG (a file Image) and a `Model3D` with `src` the STL and `download` the 3MF; `ImageService.annotate` gives the Model3D its `model` state (`annotateFileImages`, `engine/imagegen/store.ts`) and the page fetches the STL from the file route, which serves `.stl` and `.3mf` as downloads (`servedProjectFile`). LookAt can look at the PNG (`models/` is one of its areas).

## Gotchas
- **Windows starts `openscad.exe`, never `openscad.com`.** Bun 1.3.13 does not start a `.com` program named by a path with backslashes (ENOENT, "Executable not found in $PATH"; with forward slashes it starts), and `openscad.exe -o` writes the same lines, to stderr, with the same exit codes (both measured 2026-11-27). The first live check failed on exactly this, because the unit tests run under vitest's Node, which starts either.
- **A slice needs every preset flattened, includes and all.** The command line resolves neither `inherits` nor `include`: a bare leaf slices on built-in defaults. The P2S machine's start, end, layer-change and filament-change G-code live in `include`d templates; a first probe that flattened `inherits` only sliced a 20 mm cube with a generic parent's start G-code (9 min; with the templates, 22 min, the P2S's own heating and levelling included). `flatten` is bambu-studio-ai's order (MIT; `CREDITS.md`).
- **The build plate is a project setting, not a preset one**: `curr_bed_type` goes into the process preset, or the command line assumes a Cool Plate (the wrong bed temperature).
- **The model can write anywhere in the project, links included**, so nothing is written through a link: each folder on the way to the output is `lstat`ed and must be a real folder really inside the project (`folderFault`, `build.ts`), OpenSCAD and Bambu Studio write only into a fresh `mkdtemp` folder under `.cynco/tmp`, outputs are renamed into place (a link at the target is replaced), a stale `.3mf` is removed with `unlink` (a link goes, not its target), and a source with a second name is refused.
- **A design must not read past the project fence.** OpenSCAD's language runs no program and writes no file, but `include`, `use`, `import` and `surface` read; `referenceFault` is the fence, and a computed file name is refused rather than guessed. Fonts (`text()`) are read from OpenSCAD's own and the system's font folders, which is allowed.
- **Never start a print.** The prompt says it (`PROJECT_WORK`, `engine/projects/profile.ts`), the tool description says it, and the tool cannot: it has no printer client. Starting prints from CynCo (LAN mode, an access code, a yes per print) is a separate decision the owner deferred on 2026-11-27.
- **Time and grams are Bambu Studio's prediction** for the Generic preset of the material, not a measurement; the owner's OVERTURE PLA+ and Polymaker ASA/TPU are sliced as Generic PLA/ASA/TPU.
- **A mesh, not a design, cannot be edited**: the text says to write a `.scad` that `import()`s it and build that (scale, cut a flat base, add a pad).
- The unit tests use stand-in programs (`engine/__tests__/print3d/`); the real OpenSCAD and Bambu Studio are proved only by `check.ts` on a PC that has them. CI's Ubuntu has neither.
