# engine/apps

## Purpose
The owner's other local-LLM projects (a game, a screenplay tool, a pay-equity service) start model servers of their own, and the owner asked CynCo to figure out what those are and manage them: "they are more or less aspects of the same cynco system just different use cases". This package is the one rule for that: when CynCo needs the GPU and an app's model server holds CynCo's model port, CynCo names the app, stops that server, and starts it again when its own work is done. A chat turn and a daemon one-shot both go through it. Design, survey of the apps and the decisions made: `docs/decisions/2026-11-11-local-llm-apps.md`. It must never stop a server it has not identified on CynCo's own port, never start a script that was not demonstrably running that server, and never leave an app that is in use without its server.

## Key files
| File | Role |
|---|---|
| `registry.ts` | `~/.cynco/apps.json`: the apps CynCo knows (`LocalApp`: folder, launch script, how to start it, `manage`), read tolerantly, written atomically. |
| `portTree.ts` | The process on a port with its ancestors and their command lines (`readPortTree`), and the whole process list (`listProcesses`); PowerShell + CIM, Windows only, bounded. |
| `identify.ts` | `identifyPortHolder`: engine, app, foreign or unknown. Finds the launcher script in the ancestors (`launcherOf`), matches it to the registry (`matchApp`), and otherwise looks for it in the owner's project folders (`discoverApp`, `projectDirs`) and registers what it found with the evidence. |
| `displace.ts` | `displaceApp` (stop the server, say which app, write down what is owed in `~/.cynco/displaced-apps.json`), `appInUse`, `restoreDisplacedApps` (start again what is owed), `launchOutsideJob`. |
| `gpu.ts` | The rule wired for its callers: `lazyAppDeps` for `ProcessManager.ensureRunningLazy`, `takeGpuForOneShot` for the daemon's `TaskRunner`, `giveGpuBack` for both. |
| `gitBash.ts` | Which bash runs a launcher script on Windows: `throughGitBash` puts every bash launch through Git's wrapper `bin\bash.exe` (F222). |
| `start.ts` | Starting an app from the `start` recipe on its registry entry: `startApp` (each step left alone, started and waited for, or the reason it stopped) and `tendModelOnce` (the model port while the launcher's window is open). Every process is behind `StartDeps`. |
| `desk.ts` | The launcher a Desktop icon runs (`startFromDesk`: real processes owned as trees, their output in `~/.cynco/app-logs/`, the browser, stop on close) and the icons (`createIcons`, `shortcutArguments`). |
| `ollama.ts` | Apps with no server of their own: `ollamaLoaded` (what Ollama holds in GPU memory), `findModelUsers` (which projects name that model beside Ollama), `freeOllamaForCynco` (ask Ollama to unload, say for whom as far as that is known). Ollama's HTTP API only. |

## Important types & functions
- **`LocalApp`** (`registry.ts:49`), **`loadApps`** (`registry.ts:172`), **`saveApp`** (`registry.ts:189`) — an entry is written by discovery or by hand; `"manage": false` makes CynCo treat that app's server as any server that is not its own (F202: stopped by a chat turn, deferred behind by a one-shot).
- **`readPortTree`** (`portTree.ts:70`) — the listener first, then its ancestors, nearest first; the chain stops at a parent pid that belongs to a later process (Windows reuses pids). **`listProcesses`** (`portTree.ts:98`) throws when the list cannot be read, so nobody decides on an empty one.
- **`launcherOf`** (`identify.ts:90`) — the nearest ancestor that is a shell or interpreter running a script file: `bash x.sh`, `cmd /c x.cmd`, `powershell -File x.ps1`, `python x.py`, `node x.js`. `normalizeScript` (`identify.ts:80`) drops `./` and `../` and turns Git Bash's `/c/…` into `C:/…`.
- **`discoverApp`** (`identify.ts:145`) — exactly one of the project folders has the launcher's script, and the script's text starts a model server: that folder is the app, named after it, launched by the interpreter that was actually running (its full path, so a bare `bash` never becomes the WSL launcher, F160). Two candidates, or a script that starts no model server, is not guessed.
- **`unreadableLauncher`** (`identify.ts:105`), **`discoverByFolder`** (`identify.ts:185`) — an app started from an administrator window (F223): the command lines of its server and of the shell above it read as nothing from an engine that is not elevated, so `launcherOf` finds no script. Then the answer is the one registered app whose launcher is that kind of script and which is running (`appInUse`), or, with none registered, the one project folder something is running from that has exactly one script of that kind which starts a model server and names the port; a checkout of CynCo is never a candidate. Asked only when the nearest shell cannot be read: a shell that can be read and matches nothing is still somebody else's.
- **`identifyPortHolder`** (`identify.ts:245`) — a CynCo engine's server is recognised first, exactly as `engine/llama/portOwner.ts` does; an app comes from the registry or from discovery (which saves it); the rest is `foreign`, and an unreadable port is `unknown`.
- **`appInUse`** (`displace.ts:67`) — some process outside the launcher's own tree has the app's folder in its command line or executable path. The launcher's ancestors are not part of that tree: the terminal that ran the launcher usually ran the app too.
- **`displaceApp`** (`displace.ts:130`) — in use: the debt is recorded before the server is stopped, and the notice says the app is answered by CynCo's server meanwhile when the stopped listener was a llama-server (same port, same API). That is true for the one port: **`launcherSiblings`** (`displace.ts:88`) finds the other servers the launcher started (a `--port` on the command line, not the server and not what the server started), and the ones that are gone after the stop are named in the same notice, with the sentence that CynCo does not stand in for them (F226; dndai's embeddings on 8082). Not in use: a leftover, stopped and not owed anything. A process list that cannot be read counts as in use.
- **`stopProcess`** (`gpu.ts:53`) — `{ stopped: true }` when the pid is gone within three seconds, else `{ stopped: false, why }`; Windows' "Access is denied" is worded as what it means, the process was started as administrator and CynCo was not (F223). `displaceApp` then returns `refused`: it takes back the debt it wrote, says the server holds the port, that CynCo could not stop it, why, and what to do (close that window, or the Desktop icon when the app has a `start` recipe), and nothing is called stopped. `takeGpuForOneShot` and the lazy engine both say "stopped" only after the port is free.
- **`restoreDisplacedApps`** (`displace.ts:209`) — for each debt: older than `MAX_DISPLACED_AGE_MS` (`displace.ts:30`, 24 h) is dropped; a one-shot holding the GPU or anything on the port leaves it owed; an app no longer running is dropped and said; otherwise the launcher is started with `launchOutsideJob` (`displace.ts:285`) and the debt cleared. A failed start stays owed. Never throws.
- **`lazyAppDeps`** (`gpu.ts:107`), **`takeGpuForOneShot`** (`gpu.ts:151`), **`giveGpuBack`** (`gpu.ts:179`).
- **`freeOllamaForCynco`** (`ollama.ts`) — one `POST /api/generate` with `keep_alive: 0` per model Ollama holds on the GPU; the notice names the app the model belongs to when the registry (`ollamaApps`) says so; otherwise it lists the projects whose files name the model (**`findModelUsers`**, `ollama.ts`: awaited reads, a four-second budget, no checkout of CynCo; what a finished search found is remembered as `ollamaFindings` for `FINDING_MAX_AGE_MS`, a week), and registers one of them only when it is the single one running (`appInUse`), or says the model alone when no project names it (F220). A model whose every known app has `"manage": false` stays loaded and that is said; `"ollama": { "manage": false }` switches the whole thing off; `ollama.url` moves it. Nothing is owed afterwards: Ollama reloads on the app's next request. Never throws; Ollama not running is nothing loaded. **`loadRegistry`** / **`saveOllamaApp`** / **`setAppManaged`** (`registry.ts`) read and write the whole file and keep the sections they do not touch.

- **`throughGitBash`** (`gitBash.ts:64`) — a launch whose interpreter is `bash` or `sh`: Git's inner `usr\bin\bash.exe` (what the process list shows, so what discovery records) becomes the wrapper beside it, and a bare name or the WSL launcher becomes Git's wrapper (**`gitBash`**, `gitBash.ts:47`: beside the `git.exe` on PATH, then the usual install folders). Another real bash and every other interpreter are returned unchanged; with no Git for Windows it throws, and the caller says so. `launchOutsideJob` and `runChild` both call it.
- **`AppStep`** (`registry.ts:22`), **`AppStart`** (`registry.ts:47`) — the `start` section of an entry of either kind, written by hand: steps in order (`port`, `url` or `check` to tell it is running; `exe`, `args`, `cwd` to start it; `model: true` for the entry's own `launch`; `keep` for what stays, `always` for what is started even when it answers), `open`, `icon`. Read tolerantly; **`findApp`** (`registry.ts:203`) is the entry by id, whichever kind.
- **`startApp`** (`start.ts:124`) — per step: running already is left alone; not running with no `exe` ends the start; otherwise it is started and waited for, and a process that ends with an error, or the time running out, ends the start with the reason and the end of its output. A command that exits 0 is waited on (a service start hands over to the service). A step marked `always` is started even when it already answers (what only stays up while something holds it: the WSL distro dndai's database lives in). A step that starts, runs or asks Docker is refused before anything is run or asked (**`namesDocker`**, `start.ts:65`; the owner's rule, F227). The model step asks `identify` when the port is bound: CynCo's own server answers the app, the app's own is "already running", anything else is named and left. Nothing is opened unless every step is up.
- **`tendModelOnce`** (`start.ts:185`) — one look at the model port: a debt CynCo owes this app is taken over (**`forgetDebt`**, `displace.ts:51`), and the app's own server is started when the port has been free for two looks.
- **`startFromDesk`** (`desk.ts:138`) — the registry entry, `startApp` with **`runChild`** (`desk.ts:44`: a child of the launcher, owned by `ownProcessTree` unless `keep`, output to **`stepLog`**, `desk.ts:39`), the address opened if it is `http`/`https` (**`openAddress`**, `desk.ts:106`), then the wait: every `pollMs` it says which child stopped, ends when all have, and tends the model. `signal` aborted (the window closed, Ctrl+C) stops everything it started.
- **`shortcutArguments`** (`desk.ts:242`), **`planIcons`** (`desk.ts:253`), **`createIcons`** (`desk.ts:300`) — one `.lnk` per entry with a `start` section, on the Desktop Windows reports, to `cmd /c if exist <checkout>\scripts\cynco-app.cmd (… <id>) else (echo why & pause)`.

## Data flow
1. A lazy chat engine needs the model and finds a healthy server on its port: `ensureRunningLazy` asks `portOwner`, which is `lazyAppDeps(port).portOwner` (`engine/bootstrapProvider.ts`), which is `identifyPortHolder`.
2. `app`: `takeFromApp` runs `displaceApp`, which says which app on the lazy wait's notice channel (`ProcessManager.onWaiting` → `governance.alert` → a `model:` line in the chat, desk and phone) and in the log. The engine then loads its model on the freed port; the app's next request is answered by it.
3. A daemon one-shot: `TaskRunner.run` calls `takeGpu` before its busy check (`engine/daemon/main.ts` wires `takeGpuForOneShot`), so an app's server no longer defers the run; what the daemon did is logged and sent to the phone through the daemon's ntfy channel.
4. CynCo is done: the lazy engine's idle unload and its shutdown (`engine/main.ts`), and the end of every one-shot, call `giveGpuBack`. An engine or daemon that starts also calls it, for a debt left by one that died.
5. Ollama: `ProcessManager.relieveGpu` (wired in `engine/bootstrapProvider.ts` for every engine) is asked by the pre-spawn check when the card is short of VRAM (`checkSpawn`, `engine/llama/hostResources.ts`), and `engine/daemon/main.ts` asks before every one-shot's busy check; both are `freeOllamaForCynco`.
6. A mission: `scripts/dispatch-mission.sh` runs `bun scripts/cynco-apps.mjs take --by "the mission <name>"` before its kill sweep (the same `identifyPortHolder` + `displaceApp`, then `freeOllamaForCynco`); the mission engine's eager start asks `ProcessManager.takePortFromApp` (wired in `engine/bootstrapProvider.ts`) before it clears its port; the engine gives back at shutdown, and `scripts/cynco-mission-driver.mjs` runs `cynco-apps.mjs give-back` after a hand kill. The engine booted after a mission is lazy, so it does not take the GPU back from the app (F219).

7. The owner double-clicks an app's Desktop icon: `cmd` runs `scripts/cynco-app.cmd <id>`, which runs `bun scripts/cynco-apps.mjs start <id>` → `startFromDesk`. It reads `~/.cynco/apps.json` itself and does not ask the running engine for anything. `bun scripts/cynco-apps.mjs icons --repo <checkout>` makes the icons.

## Switched on by
Nothing to set: it acts only when a server that is not a CynCo engine's holds the model port. With no registry entry and no launcher that can be found, the behaviour is F202's. `"manage": false` in `~/.cynco/apps.json` switches it off per app; deleting `~/.cynco/displaced-apps.json` forgets what is owed. Nothing else depends on this package; `engine/llama` only knows the fourth answer `app` and an optional `takeFromApp`. The owner sees the apps and switches `manage` per app on the dashboard's Missions tab (`engine/dashboard/appsApi.ts`, `/api/apps`); a remote page reads and cannot switch. An app is started from its Desktop icon only when its entry has a `start` section (written by hand; `docs/decisions/2026-11-11-local-llm-apps.md`, decision 7); delete the section or the `.lnk` and nothing starts it. The dashboard does not start apps.

## Gotchas
- A process's working directory cannot be read from the process list, which is why an app is found by looking for its launcher script and not by asking where the launcher ran.
- A restarted server must not be the engine's child: the engine sits in a kill-on-close job (F131), so `launchOutsideJob` has the WMI service create the process (`Win32_Process.Create`). It gets the owner's profile environment, not the engine's: a launcher that needs a variable set only in one shell will not find it.
- Only the listener is stopped (`stopProcess`, `gpu.ts:53`), not its tree: an app's launcher script must be left to run its own exit handler (dndai's stops its embeddings server). CynCo does not stand in for what that handler stops; the notice says what went down (`docs/decisions/2026-11-11-local-llm-apps.md`, decision 9).
- An app's request to Ollama after CynCo asked it to unload reloads the model beside CynCo's: CynCo says what it unloaded and does not police what Ollama does next (`docs/decisions/2026-11-11-local-llm-apps.md`, decision 5).
- CynCo's engine is not elevated. An app started from an administrator window can be named and cannot be read further or stopped (F223): `refused`, said once, no debt, and the turn goes to the fallback or is refused; it is never waited behind. Tests that start their own stand-ins cannot show this, which is why `cannotStop.test.ts` and `identifyUnreadable.test.ts` give the stop and the process reader the answers an elevated process gives.
- **Never Docker** (F227, decision 10): an app's launch may only start what the owner already runs beside the models. A recipe is written from what runs on this PC, not from the app's documents; `noDocker.test.ts` fails when a recipe in this repository names Docker, and the launcher refuses such a step in any registry file.
- Three bashes on one PC (F222): Git's wrapper runs a launcher, Git's inner bash started by itself has no `dirname` or `date`, and a bare `bash` from anything but a Git Bash terminal is WSL. Never spawn a recorded `launch` directly: go through `launchOutsideJob` or `runChild`.
- A process started with `launchOutsideJob` has no window (session 1, window handle 0). That is why the desk launcher does not use it: what an icon starts must be something the owner can see and close. It is also why the dashboard does not start apps.
- The launcher's window and the engine can both want to start an app's server when CynCo lets go of the port. The window takes over the debt (`forgetDebt`) at its next look, so normally only the window does; if the engine's give-back comes first, its server holds the port, the window finds it bound and starts nothing, and that server stays after the window is closed until CynCo next needs the GPU (a leftover, decision 2).
- A step whose port is already bound is taken as running, whoever holds it: a different project's dev server on 3000 makes dndai's web app "already running".
- `desk.test.ts` starts real stand-in processes and, on Windows, writes a real shortcut into a temp folder and runs its command line; `gitBash.test.ts` starts a script through the real out-of-job start where Git for Windows is installed. Neither touches the Desktop or `~/.cynco`.
- Pinned by `engine/__tests__/apps/identify.test.ts`, `displace.test.ts`, `gpu.test.ts` and `standIn.test.ts`; the last runs the whole path with real processes on Windows (a launcher script, the server it starts, a client in the app's folder, the real reader, stop and out-of-job start).
- `ollama.test.ts` runs against a stand-in Ollama on a port the OS chooses; no test reaches 11434 (the suite refuses it).
- A project that names an Ollama model is evidence, not an app (F220): `ollamaFindings` in `apps.json` is what a search found and is never shown or managed; only `ollamaApps` are. An app that runs on another machine (screenplayer, on the NAS) has no process here, so it is never registered by itself: the owner adds it by hand (the entry is in `docs/decisions/2026-11-11-local-llm-apps.md`, decision 5). Deleting `ollamaFindings` makes the next unload search again.
- The restart's command line is quoted by the Windows C runtime's own rules (`windowsCommandLine`, `displace.ts`; F217): backslashes before a quote and at the end of a quoted argument are doubled. `engine/__tests__/apps/commandLine.test.ts` reads each one back with those rules.
