# engine/power

## Purpose
The engine's and the daemon's relationship with the machine's power state, in two parts that share one signal. `activity.ts` is the signal: a process-wide refcount of what is open — a turn, a one-shot child, an in-flight model request, the picture queue (`engine/imagegen/service.ts`, kind `picture`) — with edge callbacks on 0→1 (`onBusy`) and 1→0 (`onIdle`). `awake.ts` consumes it to keep Windows from sleeping while anything is open (a `SetThreadExecutionState` helper that lives exactly as long as the busy stretch); `engine/llama/lazyLoad.ts` consumes it to unload the model only when nothing has been open for a while. Nothing here ever puts the machine to sleep: Windows' own idle timer does that, and the doorman (`scripts/doorman/`) wakes it. Design and rationale: `docs/decisions/2026-11-08-wakefulness-design.md` (slices 2 and 3).

## The box reporter (`reporter/`)
Every 15 s it looks at the box; it pushes a sample when something worth telling changed (`fingerprint`: a service up or down, a model loaded or in use, who holds the GPU, the engine's model state) or 60 s have passed, and pushes events with the time they happened. What it reads, and from where:

| What | Read from | File |
|---|---|---|
| Asleep and awake, what Windows says woke the box, restarts | the System log (`Power-Troubleshooter` 1, `Kernel-Power` 42, `Kernel-General` 12/13), by PowerShell, at the first look, after a gap in its own looks and every 10 minutes | `reporter/powerEvents.ts` |
| Each GPU's temperature, memory, load and the processes on it | `nvidia-smi`, at most once in 55 s | `reporter/gpu.ts` |
| Seconds since the owner's last keyboard or mouse input | `GetLastInputInfo` through `bun:ffi` (the task runs in the owner's session) | `reporter/idle.ts` |
| The engine: up, model state, a turn running, what it has open | `GET /api/session` on loopback with the shared inference token, read from `tokens.json` and never written; `activity` there is `activity.snapshot()` | `reporter/engineFacts.ts` |
| The model port: a server there, which model, a slot working | `/health`, `/props`, `/slots` on `LOCALCODE_PORT` | `reporter/engineFacts.ts` |
| Who holds the GPU by CynCo's reckoning | `gpu-busy.json`, else the port's process tree against the apps registry | `reporter/engineFacts.ts` |
| Services and whether something depends on them now | the dashboard, the embedding service's `/health`, the daemon in the process list | `reporter/engineFacts.ts` |
| Scheduled-job runs | each mission's `runs.jsonl`, from where the last look ended | `reporter/jobs.ts` |
| `the event loop was blocked` and the embedding outage lines | new lines of `engine-headless.log` | `reporter/logTail.ts` |

- **`createReporter`** (`engine/power/reporter/main.ts:74`) — one look (`tick`): the System log when due, the log tails, a sample, then up to ten backlog batches. **`main`** (`engine/power/reporter/main.ts:190`) wires the real sources (`liveSources`, `engine/power/reporter/main.ts:170`) and runs it every `LOOK_MS` (`engine/power/reporter/main.ts:35`).
- **`gatherSample`** (`engine/power/reporter/sample.ts:39`) — a source that throws or does not answer in 8 s leaves its field `null`; the sample still goes out. **`fingerprint`** (`engine/power/reporter/sample.ts:68`) is what makes a sample go out before the beat.
- **`Outbox`** (`engine/power/reporter/outbox.ts:38`) — what has not reached the watcher: at most 5,000 records (about three days), the oldest dropped beyond that and the loss itself reported (`reporter.dropped`); on disk (`<cyncoHome>/watch/outbox.jsonl`) only while there is a backlog. A batch the watcher calls bad (400, 413) is not sent again; any other failure keeps it. An unreachable watcher is said in the log at the first failure, then every ten minutes, and once when it answers again.
- **`powerEventsFromRows`** (`engine/power/reporter/powerEvents.ts:49`) — the System log rows as `power.sleep` / `power.wake` / `power.boot` / `power.shutdown`. The wake source is passed on in Windows' words and judged by the watcher, never here (F221: eight wakes by network traffic all read "Power Button").
- **`holderReader`** (`engine/power/reporter/engineFacts.ts:177`) — a one-shot, else `engine`, `app:<id>`, `foreign`, `none` or `unknown`. It composes `readPortTree`, `classifyPortOwner` and `matchApp` and does **not** call `identifyPortHolder`, which registers an app it discovers in `apps.json`: observing must not write. An app the engine has not met yet therefore reads as `foreign`. For the same reason the one-shot's claim is read by **`readBusyClaim`** (`engine/power/reporter/engineFacts.ts:154`) and not by `readGpuBusy`, which deletes a claim whose process is gone.
- **`readInferenceToken`** (`engine/power/reporter/engineFacts.ts:51`) — the shared inference secret, read only; `loadOrCreateTokens` is never called here, because it mints over a file it cannot parse.
- **`logLineEvents`** (`engine/power/reporter/logTail.ts:35`), **`FileTail`** (`engine/power/reporter/logTail.ts:61`) — the engine log has no times, so a line is stamped with when it was read, and a file never looked at before is started at its end.
- The push protocol's types are `engine/power/reporter/types.ts`; the wire format is in `scripts/doorman/CLAUDE.md`.

**Switched on by** `LOCALCODE_WATCHER_URL` (the watcher's address, `http://100.110.117.10:9171`). Unset, `main` says `[watch] off` and exits 0 having gathered nothing. `scripts/run-box-reporter.cmd` sets it to the doorman unless it is already set, so on the owner's PC the switch is the task: `scripts\cynco-services.ps1 register watch`, `start watch`, `stop watch`. `bun engine/power/reporter/main.ts --once` is one look, sent, and out. Its log is `~/.cynco/box-reporter.log`; its state is `~/.cynco/watch/` (delete the folder and it starts from the end of each log and three days of the System log). Nothing depends on it: with it stopped the box is unwatched and says nothing, and the engine, the daemon and the doorman are untouched. It needs `engine/apps`, `engine/daemon/gpuBusyFile.ts`, `engine/llama/portOwner.ts` and `engine/security/localToken.ts` for their readers only.

## Important types & functions
- **`ActivityRegistry`** (`activity.ts:16`) — the refcount. `begin` returns an idempotent `end`; listeners fire only on the 0↔1 edges, so overlapping activities produce one busy and one idle.
- **`activity`** (`activity.ts:58`) — the one instance; producers import it rather than threading a registry through constructors.

## Gotchas
- Producers must call `end()` on every exit path (a `finally`), or the PC never sleeps and the model never unloads. The returned closure is idempotent so a double call is safe.
- The registry is per process: the engine, the daemon and each one-shot child hold their own helper. That is intended — each process keeps the PC awake for its own work and the helper exits with its parent. `snapshot()` is read from outside through `/api/session` (`activity`, `engine/main.ts`), which is how the box reporter tells a model in use from one that is only loaded; a daemon one-shot's work shows as `gpu-busy.json` instead.
- The reporter does not say "going to sleep" before the box sleeps: it reads the sleep back from the System log after the wake, stamped with the time it happened. While the box is asleep the watcher's page says it is silent with no sleep reported yet (`docs/NOW.md`).
- The reporter's process is `bun engine\power\reporter\main.ts`. The selectors that find or kill "the engine" match `engine/main.ts` or `engine\main.ts` (`scripts/dispatch-mission.sh`, `scripts/cynco-mission-driver.mjs`, `scripts/cynco-widget.ps1`, `scripts/cynco-services.ps1`), which that command line does not contain, so a mission dispatch leaves it running; `reporter.test.ts` pins it (the F215 class: a selector written before a second thing lived there).
- On Windows `nvidia-smi` gives no per-process memory, so a process is reported as being on the card, not by how much it holds, and `[Insufficient Permissions]` rows are dropped.
- Reporter tests use stand-in servers on port 0 and injected sources. `engine/__tests__/power/replay20261111.test.ts` starts a real `watcher.py` on 127.0.0.1 and needs a Python 3 on PATH (it says so and skips without one).
