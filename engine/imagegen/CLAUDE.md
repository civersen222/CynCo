# engine/imagegen

## Purpose
Pictures for RenderUI `Image` elements that carry a `prompt` instead of a URL (F174): the engine paints them on the operator's ComfyUI server (the 4070 Ti Super PC) and keeps them with the project. `annotate` runs synchronously on the one final spec of a RenderUI call in a project chat: each prompted Image gets an engine-only `image` state (**`UiImageState`** (`engine/bridge/protocol.ts:183`); its event is **`UiImageEvent`** (`engine/bridge/protocol.ts:191`)) the surface draws at once as a placeholder, and a job unless the picture is already made or already in flight. The model's turn never waits: jobs run one at a time beside it, and a `ui.image` event keyed on the image key (never on a surface) tells the page when a picture is ready. Each picture lands in `<project>/images/<key>.png` beside a JSON sidecar recording exactly how it was made — the prompt, seed, checkpoint, the filled graph submitted and ComfyUI's output names — which a later image → 3D → STL step will read. An unset, unreachable or misconfigured server is a named reason in the card, the tool result and the log; nothing crashes. This package may import from `engine/projects/` (`layout.ts`, `history.ts`) and the type-only `engine/bridge/protocol.ts`; it never imports `conversationLoop`. Status: the loop hands it each final RenderUI spec (`emitFinalUiRender`, through the loop's `images` option), `ui.image` is an `EngineEvent`, and `main.ts` builds it, probes in the background and shuts it down in `cleanShutdown`; the dashboard serves the pictures (`GET /api/projects/:slug/images/<key>.png|json`, `engine/dashboard/server.ts`), a reloaded chat gets each picture's state back (`withValidatedSurfaces`, `engine/projects/api.ts`), and the page draws every state and fills it in on `ui.image` (`engine/genui/CLAUDE.md`).

## Important types & functions
- **`comfyConfig`** (`config.ts:159`) — `(env) → { ok, cfg } | { ok: false, reason }`, never throws; run once when `ImageService` is constructed, so a change needs an engine restart. Refusals: unset (`UNSET_REASON`, `config.ts:118`, names `LOCALCODE_COMFYUI_URL` and an example address), a non-http(s) URL, a size that is not `WxH` in multiples of 64 from 512 to 2048 (refused, never defaulted), and every workflow-file problem prefixed `LOCALCODE_COMFYUI_WORKFLOW:`.
- **`comfyUrl`** (`config.ts:38`), **`comfySteps`** (`config.ts:62`) and their siblings — one pure reader per variable in the shape `envVarScan.mjs` derives a default from; the clamps (steps 1–150, cfg (0, 30], timeout 30–3600 s) apply to env values only.
- **`ComfyConfig`** (`config.ts:99`) — base URL (path prefix kept, no trailing slash), host, port, configured checkpoint or null (pick at probe), the workflow (`ComfyWorkflow`, `config.ts:89`: source, sha256 or `builtin-1`, graph, `usesCheckpoint`), size, steps, cfg, timeout, sampler, scheduler, negative prompt.
- **`BUILTIN_WORKFLOW`** (`workflow.ts:34`) — CheckpointLoaderSimple → two CLIPTextEncode → KSampler → VAEDecode → SaveImage, placeholders as whole string values.
- **`parseWorkflow`** (`workflow.ts:80`) — refuses non-JSON, a UI-format export (top-level `nodes` + `links`), a node that is not `{class_type, inputs}`, an unknown `{{x}}`, a numeric placeholder inside a longer string, no `{{prompt}}`, and no SaveImage node.
- **`fillWorkflow`** (`workflow.ts:138`) — walks the parsed object on a `structuredClone`; a whole numeric token becomes a number, a string token is replaced in place by a function replacement (so `$&` and a literal `{{seed}}` in a prompt stay inert); keys, `class_type` and `_meta` are never touched.
- **`ComfyClient`** (`client.ts:52`) — every call carries its own `AbortSignal.timeout` (`CLIENT_TIMEOUTS`, `client.ts:34`: stats 3 s, models and nodes 5 s, submit 15 s, history 5 s, view 30 s, interrupt/queue 2 s), and every failure is a **`ComfyError`** (`client.ts:18`) whose `reason` the card and the model show as is; an unreachable server names `--listen` and the firewall port. `submit` (`client.ts:133`) returns the server's `prompt_id`, which wins over the one sent (older servers ignore it); a 400 becomes `ComfyUI refused the workflow: … node <id> (<class>): …`, cut to 300 characters, and is the one `ComfyError` marked `refused` (ComfyUI queued nothing, so the worker cancels nothing). `history` (`client.ts:150`) returns null while pending. `download` (`client.ts:166`) refuses a bad reference before asking, an over-cap body by Content-Length or while streaming, and bytes without the PNG signature.
- **`probeComfy`** (`client.ts:253`) — `/system_stats`, then the checkpoint (only when the workflow has `{{checkpoint}}`: a configured name must be listed exactly; otherwise the alphabetically first `/juggernaut/i`, else `/xl/i`, else a refusal — the built-in graph is SDXL-only), then `/object_info/<class>` for every class the workflow uses. Never throws.
- **`imageKey`** (`store.ts:118`) — 32 hex of sha256 over the canonical JSON of prompt, negative, seed, size, steps, cfg, sampler, scheduler, checkpoint (`'auto'` when picked) and workflow sha; known before any network call; `KEY_RE` (`store.ts:30`) is a key's only spelling, and the page checks its own copy of it before it builds a URL. **`seedFor`** (`store.ts:106`) — the first 48 bits of sha256(prompt + negative): the same prompt paints the same picture everywhere in a project; element ids are left out so a renamed id never repaints.
- **`ImageSidecar`** (`store.ts:50`) — schema 1: status, reason, `runId`, every generation parameter, `apiPrompt` (the filled graph submitted), `comfy` (host, promptId, outputs), sha256/bytes, timings (`queueMs` enqueue→submit, `genMs` submit→history entry, `execMs` from ComfyUI's own timestamps) and the origin. **`readSidecar`** (`store.ts:254`) type-checks every field; a bad file reads as no record. It reads only a regular file under a size cap (`readSmallFile`, opened non-blocking and checked on the descriptor), so a planted FIFO, a link to /dev/zero or a huge file is no record at once instead of a frozen engine thread.
- **`readOrigins`** (`store.ts:288`) / **`recordOrigins`** (`store.ts:311`) — `images/index.json`, `<chatFile>#<toolId>#<elementId>` → key, a null-prototype map keeping only well-formed pairs, capped at `ORIGINS_CAP` (oldest dropped); read the same guarded way.
- **`storeFault`** (`store.ts:217`) — why the engine must not store pictures in a project: `images/` and `.cynco/tmp/` must each be a real folder inside it (not a link or junction, nothing whose real path leads out) or not exist yet, and `.gitignore` a regular file or absent. Checked at annotate (every picture `off` with the reason), at job start and again at the PNG write (the job fails with it); `writeSidecar`/`recordOrigins` refuse on their own too. Every write is a fresh file created `wx` (an unguessable temp name, or the `.part` after removing whatever was there) and renamed into place, so a link planted at a target or a temp name is replaced, never written through.
- **`promptedImages`** (`store.ts:355`) — every `Image` with a non-empty prompt reachable from the root, in draw order: the one definition both `annotate` (what to queue) and `withValidatedSurfaces` (what to look up on reload) use.
- **`servedImage`** (`store.ts:392`) — the image route without HTTP: `<32 hex>.png|json` only, `realInside` both the project and its `images/`, a regular file, at most 32 MB, PNG signature checked (415 otherwise); `.json` serves `publicSidecar` (`store.ts:378`) only.
- **`storedImageState`** (`store.ts:430`) — what a reloaded chat's Image shows, found through the origin index (the exact picture shown live, even after the knobs changed); a queued/running record under another `runId` reads `failed: interrupted …` (`effectiveStatus`, `store.ts:280`), a `done` record whose PNG is gone reads `failed`, a missing or unreadable record reads `off`, and an origin the index does not hold reads `off: this picture was not generated`.
- **`ImageAnnotator`** (`service.ts:50`) — the one method the loop holds (`ConversationLoopOptions.images`): `annotate(spec, at: AnnotateAt)` → **`Annotation`** (`service.ts:48`) `{ note, start }`. **`AnnotateAt`** (`service.ts:39`) is the bound project chat (`{ dir, slug, chatFile }`, or null for a coding session), the toolId, the surface and whether the call was cut off.
- **`ImageService`** (`service.ts:158`) — constructor deps `{ env?, fetchFn?, emit, now?, log?, pollMs?, timeoutMs? }` (the last two are test seams). `probe` (`service.ts:204`) logs `[imagegen] ready: …` / `not ready: …` / `off: LOCALCODE_COMFYUI_URL unset` once per state change; `ensureReady` (`service.ts:243`) reuses a failure for 60 s and a success for 10 minutes (each edge pinned with an injected clock).
- **`ImageService.annotate`** (`service.ts:251`) — synchronous, never throws (a throw is logged and turns every prompted Image `off` with the reason). Off for no project, a config refusal, a cut-off call, an engine shutting down, a store the model tampered with (`storeFault`), past 6 distinct pictures per call (`PER_CALL_CAP`, `config.ts:28`), a full queue (24 waiting, `QUEUE_CAP`, `config.ts:30`); otherwise in flight → that job's status, done with its PNG → `done`, anything else → a `queued` sidecar, an origin and a job. Returns the tool-result `note` (`Pictures: …`) and `start`, which kicks the worker after the final frame. A call whose pictures are all made already queues nothing, so no job's commit would carry the origins it recorded: it commits `images/index.json` (and `.gitignore`) itself, beside the turn (`images: <n> shown again`).
- **`ImageService.runJob`** (`service.ts:431`) — probe, fill, sidecar `running` with `apiPrompt` BEFORE the POST, submit, emit `running`, poll `/history` every `pollMs` (three failed polls in a row give up). Once the POST may have reached ComfyUI, every give-up but a 400 refusal — a lost POST answer, the failed polls, the deadline, a throw — first withdraws the prompt (interrupt + dequeue by id), so the next job never makes two prompts on the server. Then read `execution_error`/`execution_interrupted`, pick the first `type: 'output'` image across outputs by node id, download to `.cynco/tmp/<key>.part` (created `wx` after removing anything planted there), rename to `images/<key>.png`.
- **`ImageService.whenIdle`** (`service.ts:392`) — resolves once the worker has nothing left to do, commits included (a cache hit's too); for tests and `check.ts`, never the loop.
- **`ImageService.record`** (`service.ts:576`) — sidecar, journal (`image.generated` / `image.failed`), `ui.image` event and log line in one synchronous step, then `finish` (`service.ts:607`) commits.
- **`ImageService.shutdown`** (`service.ts:644`) — marks the running job and every queued one `failed: the engine stopped before this picture finished — ask for it again`, interrupts and dequeues the running prompt by id, commits; bounded to 3 s. It cancels only while ComfyUI may still hold the prompt (`Job.onServer`: never once it finished, was refused or was withdrawn); a POST still in flight is waited for, so the cancel names the id the server answered with and lands after the prompt is queued. The cancel and the commits (a cache hit's still running among them) run side by side, so a ComfyUI that stops answering costs the bound and no more — pinned with `/interrupt` and `/queue` both hung.

## Data flow
1. At engine start `new ImageService({ emit })` runs `comfyConfig` once; `probe()` checks the server in the background and logs its state.
2. After the final `ui.render` frame of a RenderUI call in a project chat, `annotate` gives each prompted Image its `image` state, writes `queued` sidecars and the origins (after `ensureImageIgnore` (`store.ts:331`) adds `images/*.png` to `.gitignore`; a planted link named by `storeFault` turns every picture `off` instead), and returns the note for the tool result. `start()` kicks the worker.
3. The worker takes jobs FIFO, one at a time across the engine (dedupe on `dir|key`, so two surfaces showing one prompt share one job): `runJob` → `record` emits `ui.image running`, then `done` or `failed` with the reason → `commitHistory` (`engine/projects/history.ts:47`) commits `.gitignore`, the sidecar, `images/index.json` and `journal.md`. A call that queued nothing (every picture already made) commits the origin index it changed on its own.
4. The page fills every node showing the key in that project (its picture map is keyed on slug and key: two projects asking for one prompt run two jobs under one key) and fetches a done picture with the token into a blob URL; a reload (`withValidatedSurfaces`) asks `storedImageState` per Image through the origin index; the route (`engine/dashboard/server.ts`, `imageResponse`) serves bytes through `servedImage` under inert headers (`image/png` from the extension, `nosniff`, a sandbox CSP, no ACAO).

## Gotchas
- Configuration is environment variables only (`LOCALCODE_COMFYUI_*`): a profile file replaces the bundled one wholesale, and a YAML typo there would drop the setting silently. A change needs an engine restart.
- Never `fetchGuarded`/`validateUrl`: they refuse 192.168/16, and the ComfyUI URL is the operator's choice, not the model's. Plain `fetch` through an injectable `fetchFn`, as `JlensClient` does.
- The server's output filename is never a local path. It goes back to ComfyUI only as a `/view` query parameter (`URLSearchParams`); the local file is named from the key alone. Pinned by the hostile-filename tests (`../../x.png`, `C:\x`).
- The sidecar is written `running` before the POST, so a crash leaves a record naming the prompt id. Its `runId` (`RUN_ID`, `store.ts:29`) is the engine process that queued it: any reader that finds `queued`/`running` under another `runId` reports `failed: interrupted — the engine stopped before this picture finished`, and `annotate` re-queues it — a crash needs no extra plumbing. Resume after restart is not built; the sidecar keeps `promptId` so a later change could poll `/history/{id}` instead.
- Pictures are found by name only (`<32 hex>.png`), and a PNG is never named in a commit: `images/*.png` is git-ignored, and naming an ignored file makes `git add` exit 1 and journal `history.failed`.
- Everything under `images/` is untrusted on read: the model can write anywhere in a project (`gradeProjectCall`), so keys are checked against `KEY_RE`, sidecars are type-checked, origins land in a null-prototype map, every read takes only a regular file under a cap, and the route checks the PNG signature and refuses links out of the project. Nor does the engine write through anything planted: a link at `images/`, `.cynco/tmp/`, `.gitignore`, a `.part` or a temp name is refused or replaced, never followed — the fence `gradeProjectCall` puts on the model's file tools binds the engine's own writes too.
- An absent `/history/{id}` entry (`{}`) means pending or running: ComfyUI adds the entry only when the prompt ends, successfully or not.
- `MeshToFile3D` writes GLB only, and its history entry sits under `"3d"`, not `"images"`: the output picker (`outputRefs`) is generic over the kind for that later step, and an STL needs a local GLB → STL converter.
- The system prompt never varies with configuration: whether ComfyUI is set up, reachable or refusing reaches the model only through the tool result's `Pictures:` note, so the prompt stays byte-stable and the prefix cache holds.
- Events carry the key, slug and status only, never bytes: the loop's emit fans out to the TUI too, which has no use for megabytes. The page fetches the PNG from the gated route.
- One job at a time across the engine, FIFO; a job captured its `dir`, `slug` and `chatFile` at annotate time, so an abort, halt or project switch leaves it alone and it finishes into the project it was made for. A settled job still committing is not "in flight": a re-request the moment a picture fails gets a fresh job, and the old failure's event has already gone out. A job given up after its POST is withdrawn from ComfyUI before the next one goes out.
- The `[imagegen]` log lines are the latency evidence: one per RenderUI call (`<n> pictures — <q> queued, <c> already made[, <o> not generated: <reason>]`) and one per job (`<key8> done in <t>s (queue <qw>s, gen <g>s[, exec <e>s]) …` or `failed after …`). `queue` is enqueue → submit, `gen` is submit → history entry (ComfyUI's own waiting and a cold model load included), `exec` is ComfyUI's `execution_start` → `execution_success`. Read them beside the loop's `[loop] message_stop … elapsed=` line.
- The build container has no ComfyUI: the tests run against `engine/__tests__/imagegen/mockComfy.ts`, a `node:http` fake on port 0 with the real routes, a call log and failure modes (never finishes, hostile filename, oversized, not a PNG, 400 `node_errors`). A real server is proved only with `bun engine/imagegen/check.ts --generate "<prompt>"` on the operator's PC.
- Shutdown interrupts by `prompt_id` only, and only a prompt of ours that ComfyUI may still hold — an older ComfyUI may treat `/interrupt` as global, which is acceptable only because it then stops our own job. One case is weaker: a POST whose answer was lost is withdrawn by the id sent, and on an older server that ignores client ids and interrupts globally, that may stop whatever is running if ours was still queued — accepted, as the alternative leaves our prompt on the GPU beside the next one. A dispatch swap (F141) loses in-flight pictures the same way; they read `failed` and a re-render re-queues them.
