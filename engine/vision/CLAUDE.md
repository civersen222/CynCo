# engine/vision

## Purpose
CynCo's eyes: a photo attached in a project chat is looked at once by the vision model on the image box (the 4070 Ti Super's Ollama), and what it read — visible text first, then the state of lights, ports and selections, then a description — reaches both the next turn and the project's knowledge. The 5090's chat model stays text-only; the lazy/cold-GPU design is untouched. Design: `docs/decisions/2026-11-08-image-box-design.md`.

## Key files
| File | Role |
|---|---|
| `settings.ts` | `visionSettings`: the one read site of `LOCALCODE_VISION_URL` / `LOCALCODE_VISION_MODEL` (default `qwen3-vl:8b-instruct`); unset URL = no vision. |
| `lookClient.ts` | `LookClient.look`: one Ollama `/api/chat` call with the image as base64 and `LOOK_INSTRUCTION`; `parseLook` splits the reply by `TEXT:` / `STATE:` / `DESCRIPTION:`; `LookClient.ask` sends one aimed question (`askInstruction`) and returns the answer in words — the LookAt tool's path (F191); both share one private `chat`; 60 s deadline; every failure is a reason string. |
| `imageSize.ts` | `imageDimensions`: a picture's pixel size from its PNG/JPEG/GIF/WebP header, null for anything else — the zoom decides by size before decoding. |
| `tiles.ts` | The zoom (F192): `BOX_MAX_PIXELS` (4 MP, what Ollama keeps of a picture), `TILE_MAX_PIXELS` (3.5 MP), `tileGrid` (one tile, or 2–4 full-width bands with a 4 % overlap; vertical strips only for a picture more than twice as wide as tall; never quadrants, which cut a table's rows from their columns), `cropTiles` (JPEG tiles cut with the pure-JS decoders `jpeg-js`/`pngjs`; GIF/WebP cannot be cut and are looked at whole). |
| `lookRunner.ts` | `LookRunner`: looks run behind the upload — `start` (one per `<slug>/<rel>`, never doubled), `pending` (the loop waits, bounded by the client), `recent` (a small LRU, keyed by the bytes' sha256, that the turn, a re-attach of the same photo and a rescan read instead of asking again; a look whose bytes were replaced mid-flight is dropped as superseded); `PENDING_REASON` is the record the upload route writes first. |

## Important types & functions
- **`visionSettings`** (`settings.ts:19`) — `{ url: string | null; model }`; `DEFAULT_VISION_MODEL` (`settings.ts:17`). Set the two variables as permanent user variables on the PC so the desk engine and the headless phone engine see the same box.
- **`LOOK_INSTRUCTION`** (`lookClient.ts:19`) — asks for the three labelled sections in order; the order is the diagnostic use case ("which line do I pick", "is this light meant to be red"), so the look needs no aiming by the user's question and one look per photo serves the turn and the index alike.
- **`askInstruction`** (`lookClient.ts:32`), **`LookClient.ask`** (`lookClient.ts:85`), **`LookRunner.ask`** (`lookRunner.ts:79`) — the aimed look: the question verbatim plus a standing order not to invent what the picture does not show; straight to the box, nothing queued, cached or ingested. The upload-time look's `STATE` line now asks for the selected or highlighted item on a screen and how to tell (it came back `none` 4/4 on a dense screen, F191).
- **`imageDimensions`** (`imageSize.ts:11`), **`tileGrid`** (`tiles.ts:44`), **`cropTiles`** (`tiles.ts:74`) — the zoom behind `LookAt`'s `zoom` (auto: tiles when the picture exceeds `BOX_MAX_PIXELS`; on: tiles anyway; off: one look). Each tile is asked the question with its place named ("This is the top quarter of a larger picture…"), one tile at a time, and the answers come back labelled for the model to put together. Live on the 12 MP lineup photo (F192): the injury marks went from six wrong rows to four right ones; the ticked box stayed right; bold weight stayed unreliable (camera blur, not resolution); ~28 s for four looks.
- **`LookClient.unload`** (`lookClient.ts:98`) — one `/api/generate` with `keep_alive: 0`: Ollama drops the vision model from the box's VRAM now; `UNLOAD_TIMEOUT_MS` (`lookClient.ts:38`) = 10 s. The image service calls it before every transform (F194): the box's GPU is shared with ComfyUI, and with the look's 7 GB resident the 12 GB edit model took 446 s and then hit the 300 s cap; the next look reloads in seconds.
- **`parseLook`** (`lookClient.ts:49`) — a missing label is `''`, never a failure; a section reading `none` is `''`.
- **`LookClient`** (`lookClient.ts:63`), **`look`** (`lookClient.ts:78`) — plain `fetch` (never `fetchGuarded`, which refuses 192.168/16); `keep_alive: '10m'`; `options.num_ctx` = **`LOOK_NUM_CTX`** (`lookClient.ts:45`) = 8192, because Ollama's 4096 default refused a 12 MP phone photo's ~4100 image tokens with HTTP 400 (F190); `LOOK_TIMEOUT_MS` (`lookClient.ts:36`) = 60 000, cold load included; refusals: `image box did not answer: <error>`. **`makeLookClient`** (`lookClient.ts:141`) — null when no URL is set.
- **`LookRunner`** (`lookRunner.ts:26`): **`start`** (`lookRunner.ts:39`), **`pending`** (`lookRunner.ts:83`), **`recent`** (`lookRunner.ts:89`); `finish` is the ingest, bound by `makeProjectsDeps` (`engine/projects/api.ts`). **`PENDING_REASON`** (`lookRunner.ts:21`) = `looking at the picture…`. **`imageMime`** (`lookRunner.ts:112`).

## Data flow
1. The phone's Attach uploads a picture → `addKnowledgeApi` (`engine/projects/api.ts:155`) writes the bytes, records `indexed: false, reason: PENDING_REASON`, answers 201 at once, and calls `LookRunner.start`.
2. The runner asks the image box; on the answer `finish` runs `ingestFile(..., { lookInput })` (`engine/projects/ingest.ts`): `extractFile` → `imageSegments` (`engine/projects/extract/image.ts:13`) → chunks embedded by the CynCo embed server → `indexed: true, chunks: n` → `project.ingest` to the page (the Attach row turns from "kept, looking…" to indexed, the chat says "Looked at <file>") and to `ConversationLoop.noteProjectIngest` (`engine/bridge/conversationLoop.ts:1280`).
3. The next turn: `injectProjectRetrieval` (`engine/bridge/conversationLoop.ts:1286`) reads the pictures out of `IngestNotes.takeEvents` through `attachedImages` (`engine/projects/retrieval.ts:101`), waits on `pending` if the look is still in flight, and puts `formatLookBlock` (`engine/projects/retrieval.ts:117`) — `[Attached image] knowledge/<name> — text / state / description` — at the top of the per-turn `[Project knowledge]` block. The chat line names the look or the refusal (`sayVision`, `engine/bridge/conversationLoop.ts:1267`, on the `governance.alert` info channel).
4. The model asks a specific question about any project picture with the `LookAt` tool (`engine/projects/tools.ts`), which `startProjectSession` wires to `LookRunner.ask` through `ProjectToolContext.ask`; both per-turn blocks tell the model the tool exists.
5. A rescan re-looks an image through the runner (`rescanOne`, `engine/projects/ingest.ts:220`): a recent look is reused; otherwise a look is started and awaited.

## Switched on by
`LOCALCODE_VISION_URL` (and `_MODEL`). Absent: `makeLookClient` is null, `ProjectsDeps.looks` is null, the extractor answers `no vision model configured`, the turn says so once per picture and continues text-only. Nothing else depends on this package.

## Gotchas
- The page shrinks uploads over 16 MP (or 20 MB) before they leave the phone (`needsDownscale` / `downscaleImage`, `engine/dashboard/index.html`); a 12 MP phone photo arrives whole because the zoom needs the pixels (F192 reverted F190's 3 MP cap). One look still sees ~4 MP of it (Ollama's own resize); the client's 8192 window covers that.
- A dashboard tab open across an engine restart keeps the old page's JavaScript (NOW.md backlog): on 2026-11-09 the phone's tab uploaded at 12 MP under the old rule for three checks.
- One look per photo, at upload, in the background: an upload that waited on a cold 16 GB box would hold the phone's Attach for up to a minute, and a second aimed look per turn would double the cost (builder-check call in the design record).
- A failed look (`image box did not answer: …`) is recorded like a failed embedding: the file stays, the record carries the reason, a rescan retries. The turn gets **`formatNoLookBlock`** (`engine/projects/retrieval.ts:129`) with that reason — the model is told it cannot see pictures and must say so — because told only that a picture had landed, the text-only model spent twenty iterations on ImageView and pixel scripts (F190); project chats no longer offer ImageView (`PROJECT_TOOL_NAMES`, `engine/projects/profile.ts`).
- `recent` is in-memory: after an engine restart the turn falls back to the retrieval search (the chunks are in `project.db`), and a rescan re-looks.
