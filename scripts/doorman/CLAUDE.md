# scripts/doorman

## Purpose
What runs on the doorman, the always-on mini PC (Beelink N100, Ubuntu 24.04, Python 3.12, tailnet `100.110.117.10`): the front door that wakes the GPU boxes (`doorman.py`), the NAS watchdog (`naswatch.py`), ntfy (a container), and since 2026-11-12 the **watcher**, the always-on part of the metasystem. All of it is Python with the standard library only, deployed by copying files (`deploy.sh`); nothing from the TypeScript engine runs here. Designs: `docs/decisions/2026-11-08-wakefulness-design.md` (the doorman, naswatch, ntfy) and `docs/decisions/2026-11-11-metasystem-design.md` (the watcher; slice 1 of six is built: memory and the note, observation only).

The watcher never asks a box for anything. Each box pushes its own state, so watching cannot wake a sleeping box and nothing new listens on a working one. It takes no action on any box, service or app, and its core is deterministic.

## What a box pushes (protocol v1)
`POST /push` with `{"v":1,"box":"main","sentAt":iso,"records":[...]}`; the answer is `{"ok":true,"stored":n,"duplicates":n,"rejected":n}`. The types are in `engine/power/reporter/types.ts`. A record is a **sample** (`{"t":"sample","at":iso, idleS, gpus, models, holder, engine, services, integrity}`; a field the box could not read is `null`; `integrity` is `{state: "clear"|"latched"|"unusable", summary}`, since wave 15, and absent from an older reporter) or an **event** (`{"t":"event","at":iso,"kind","key","data"}`). Kinds: `power.sleep` `{reason}`, `power.wake` `{sleepAt, source}`, `power.boot`, `power.shutdown`, `job.run` `{mission, triggerId, ok, summary}`, `engine.loop_blocked` `{seconds, until}`, `service.said_down` / `service.said_up` `{service, by, text}`, `reporter.start`, `reporter.stop` `{reason}` (a stop on purpose: the box is then not watched, not silent), `reporter.dropped` `{n}`. The doorman's own facts are events of the box `doorman`: `doorman.burst` `{target, cause, forAt}`, `doorman.schedule` `{targets}`. A box name is `[A-Za-z0-9_.-]{1,64}`; a body is at most 1 MiB and 500 records.

## The model
- **Timeline** per box: `asleep` and `off` from its own power events; `awake` from its samples, and from its System log where no sample exists (between a wake and the next sleep, basis `idle sleep` when the sleep was the idle timer; or from a wake or a start until the first report, when the reporter was not running yet); `unknown` where nothing was reported. `silent` is only ever a stretch that follows a real report (F232): a gap in the samples longer than `SILENT_GAP_S` (300 s) that no sleep or shutdown covers, the time after the last sample, or the time after a wake when the box was reporting right up to that sleep. History the reporter read back out of the System log is not a heartbeat: a box is never silent before its reporter has run, and never between a start and the first logon. A stretch that would be silent is `unwatched` when the reporter said it was stopping (`reporter.stop` within 300 s after the last sample): drawn thin, said as "not watched", and never a finding.
- **Wrong by construction** (no history needed): `wake.unexplained`, a wake with no doorman burst for that box in the 120 s before it and no owner input at that moment, all of a box's in a day as one finding; `service.down`, a wanted service not answering for 180 s or more, or said to be down by its dependent; `model.unused`, a model loaded with no request for 20 minutes; `box.silent`, a closed silent stretch; `integrity.latched` (or `integrity.unusable`), a box whose samples report its integrity latch set (or its guard folder unusable): one finding per stretch, from the first sample that said so to the first that said another state, across the box's sleeps (the latch is a file that stays until it is cleared). The latch is read from the box's last `HISTORY_DAYS` (21 days) of samples and the minutes after the day, so a box that reported it set and then slept through the day still shows it, and an open stretch is a finding on every day while the box's last report says so (`integrity_bands`, read in `day_report`); a box whose last report is older than 21 days shows nothing of it. Windows' wake source is shown and never trusted: F221's eight wakes all read "Power Button".
- **Wrong by comparison** (`classify`): rolling median of 30 readings, scale 1.4826 × MAD with a floor, a reading beyond 3 sigma is a `transient` unless three in a row make a `step`; a CUSUM (slack 0.5, threshold 5, the definition of `CusumDetector` in `engine/cybernetics-core/src/metrics/index.ts`) with no outlier is a `slope`. Only step and slope are findings. A series speaks after 12 readings over 3 days and says "still learning" until then. The series today: each GPU's hourly median temperature, idle and under load.
- **Measures**, 0 to 1: asleep when it could be, loaded and unused, answering when wanted per service, each job's success rate. `None` when there is nothing to measure. Hand-off time waits for the attention loop (slice 4).

## Switched on by
The unit `watcher.service` on the doorman (`deploy.sh` installs and enables it). Stopped: `sudo systemctl disable --now watcher`; every box keeps working, the PC's reporter keeps a bounded backlog and sends it when the watcher is back. Removed: delete `/etc/systemd/system/watcher.service` and `/var/lib/cynco-watcher`; the model then starts from nothing. Nothing else depends on it. The boxes' side is `engine/power/CLAUDE.md` (the box reporter, `LOCALCODE_WATCHER_URL`).

## Gotchas
- Bind the Tailscale address only: `watcher.py` and `doorman.py` both refuse `0.0.0.0` and `::`. There is no authentication beyond the tailnet, as for the doorman's own routes: any tailnet device can push records. What that can do is bounded (one box name per push, 1 MiB) and it can never make the watcher act, because nothing here acts.
- The doorman's one exception is `127.0.0.1` beside the Tailscale address, for `tailscale serve` (it proxies to 127.0.0.1 only). Its HTTPS name reaches the same audience as the address, the tailnet, and never the internet (no Funnel; `test_doorman_https.py` pins both the unit's two binds and the deploy's serve line). `X-Forwarded-For` is believed only from a loopback peer and only when it is an address, and only to name the client in the log line; `journal_bursts.py` finds `GET /wake` anywhere in a line, so the longer prefix changes nothing it reads.
- The integrity latch a box reports is shown as its state and its summary only: in the box's status line (`; integrity latch set` or `; integrity guard folder unusable`), at the top of its card (`Integrity latch: ... (as last reported at ...)`), in the finding, and as `boxes[].integrity` in `/findings.json`. Any tailnet device can push, so `public_summary` replaces with `[a path]`, each to the end of its clause: a drive (`C:\` or `C:/`); two backslashes; two or more slashes that begin a word (`//nas/home`); a `file:` address; any word that holds a backslash; a slash or `~/` that begins a word; and the rest of a cut path after a comma, an apostrophe, a bracket or another clause mark with no space beside it, when it holds a slash or a path already cut (`C:/Users/O'Brien/x` and `C:\Users\O'Brien Smith\x` both read `[a path]'[a path]`; `_PATH_TAIL`, wave 19c). A mark with a space beside it begins a new clause, which is shown (`C:/x, then a/b`). Two cut paths joined by such marks are cut as one. A web address is cut from the letter before its colon. A relative path written with forward slashes only (`scripts/x`) is shown when no cut path comes right before it, since it cannot be told from words such as and/or. It also replaces every control character with a space and keeps at most 400 characters (`INTEGRITY_SUMMARY_MAX`). The engine's own summary (`deskIntegrity`) holds no path. Pinned by `test_watchintegrity.py`. The watcher shows the latch only after the owner has redeployed it (`deploy.sh`) after the merge.
- The page takes no input and `test_watchnote.py` pins it: no script, form, input, button, event handler, external URL, font or stylesheet. Links go to `/` and `/day/<date>` only.
- The owner's three answers to a finding are **not built** (`docs/NOW.md`): the page says so, and no table for them exists.
- Live since 2026-11-12 04:40Z (`watcher.service` on the doorman, the task "CynCo box reporter" on the main PC). The first note flagged a silence that was not one (F232): after a change to the model, the watcher's files are deployed again (`deploy.sh`) and nothing is migrated, because findings are computed from the store each time the page is asked for and are never stored.
- A box's sleep is reported after it wakes. Until then the page says the box is silent, with no sleep reported yet; it becomes `asleep` when the box's System log arrives. A silence that is still going on is a status line, not a finding.
- `journalctl --utc` changes how times are printed, not how `--since` is read: write `--since "2026-11-11 09:30:00 UTC"`. And a user outside `systemd-journal` gets "No entries" for another unit's lines; read with `sudo` (F228).
- The burst journal is trimmed by the doorman (rewritten to its newest half over 20,000 lines); the watcher notices the shorter file and reads it again, which stores nothing twice.
- Line endings: everything under `fixtures/` is pinned to LF by `.gitattributes` (`scripts/doorman/fixtures/** text eol=lf`), because a Windows checkout with `core.autocrlf=true` otherwise hands the tests CRLF copies (F231). The readers themselves must not care either way: `journal_bursts.parse` and `watcher.ingest_doorman_files` are tested with the same input in LF and CRLF (`test_doorman_bursts.py`, `test_watcher.py`), and a new reader of lines gets the same test.
- A day is the owner's local day. The offset comes from the doorman's own time zone unless `--tz-offset-min` is given; the tests always give it.
- The watcher's tests start servers on `127.0.0.1` with port 0. Nothing in this folder's tests touches the doorman.
- Python on the doorman is 3.12: no syntax newer than that, and `datetime.fromisoformat` there takes at most six fractional digits (`watchstore.parse_iso` cuts Windows' seven).
